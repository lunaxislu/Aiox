- Scope / Excluded / Allowed write-set:
  - Scope (1) Codex: `CodexAgentRuntime`(`src/adapters/codex/runtime.ts:264-279`)는 이미 child-process exit와 WebSocket close를 자체 감지해 `recordRuntimeFailure()` → optional `#onRuntimeFailed` 콜백을 호출하도록 구현돼 있고, `AttachCodexAgentRuntimeOptions.onRuntimeFailed`도 이미 존재한다. `state.recordCodexRuntimeFailed()`(`src/daemon/state.ts:1127-1167`)도 이미 구현·테스트돼 agent를 disconnect 처리하고 `agent_runtime_failed` event를 남긴다. 유일한 gap은 production factory `defaultAttachCodexRuntime`(`src/daemon/state.ts:3129-3147`, `productionAttachCodexRuntime`이 참조)가 `onRuntimeFailed`를 전달하지 않아 이 콜백 체인이 production에서 한 번도 발화하지 않는 것이다. 이 한 호출 지점에서 `onRuntimeFailed`를 실제 `state.recordCodexRuntimeFailed`(정확한 in-closure 참조는 구현자가 `createDaemonState` 클로저에서 확인)로 배선한다. 이는 `codexRuntimes`/`CodexAgentRuntime`(daemon이 직접 spawn·소유하는 managed runtime)에 대한 것이며 `codexChannelRuntimes`/`registerCodexChannel`(Codex MCP self-registration push-ingress channel)과는 무관하다.
  - Scope (2) Claude: `injectClaudeChannel`(`src/adapters/claude/injector.ts:44-74`)은 이미 fetch 실패를 ECONNREFUSED → `claude_channel_unavailable`(confirmed-death 후보), non-2xx → `claude_channel_push_failed`(ambiguous, process 생존), timeout/기타 → `claude_channel_push_unconfirmed`(ambiguous) 3종으로 분류한다. `state.ts`의 dispatch 호출부(~2038-2088)는 `injectClaudeChannel` 호출 전에 이미 `claudeChannelRuntimes.has(targetAgent.name)`을 확인하므로, 그 호출에서 받는 `claude_channel_unavailable`은 "애초에 미등록"이 아니라 "등록돼 있었는데 지금 거부당함"으로 명확히 구분된다. 현재는 이 경우도 단순 deferred dispatch 결과로만 처리되고 `claudeChannelRuntimes`나 agent 연결 상태를 전혀 건드리지 않는다(W4/controlling 확인 사실). 이 confirmed-refusal 케이스에서만 기존 `disconnectClaudeChannel()` 효과(`src/daemon/state.ts:1222-1239` — 이미 구현됨, 새 event 없이 `claudeChannelRuntimes`/`claudePendingTokens`/`claudeChannelBootFailures`를 정리하고 여전히 connected면 disconnect 전이)를 재사용한다.
  - Design constraint (재논의 대상 아님, 새 근거 없이 되돌리지 않음): push는 비동기이므로 ECONNREFUSED 결과가 resolve되는 시점에 같은 agent 이름으로 새 `registerClaudeChannel`이 먼저 들어와 map entry가 이미 새 runtime으로 교체돼 있을 수 있다. 이 경우 무조건 삭제하면 방금 재연결된 agent를 잘못 disconnect 처리한다. 구현자는 push 시점에 실제로 push한 runtime instance의 identity(예: `registeredAt`/`endpoint`, 또는 confirmed-refusal 처리 시점에 `claudeChannelRuntimes.get(agentName)`과의 object-identity 비교)를 확보해 현재 등록된 runtime이 그 instance와 여전히 같을 때만 clear/disconnect하고, 아니면 새 등록을 건드리지 않아야 한다. 이는 W12/W13이 late/replacement Claude boot-failure report를 `recorded:false`로 무시해 새 등록을 보존한 기존 선례와 같은 방향이다.
