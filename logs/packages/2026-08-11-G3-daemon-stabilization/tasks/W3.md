  - **확정 사실 — NDJSON socket input bound 부재:** daemon ingress는 UTF-8 chunk를 `buffer += chunk`로 무제한 누적하고 newline 이후에만 split/dispatch한다(`src/daemon/socket-transport.ts:63-81`). line도 크기 검사 없이 `JSON.parse`한다(`src/daemon/socket-transport.ts:242-254`). newline 없는 peer는 typed rejection 없이 connection lifetime 동안 buffer를 키울 수 있고, oversized newline-terminated JSON도 size rejection 없이 parse/dispatch된다. 별도로 bundled client의 response buffer도 같은 형태로 무제한 누적된다(`src/daemon/socket-transport.ts:284-350`); G3의 client-crash isolation 관점에서 직접 ingress gap은 server buffer지만 shared transport hardening 시 client response side도 명시적으로 범위 판정해야 한다. invalid JSON test는 newline 뒤 `invalid_json` 응답과 daemon 생존만 검증하며(`tests/unit/daemon/socket-transport.test.ts:231-277`), oversized/no-newline rejection test는 없다.
  - **확정 사실 — Claude HTTP body bound 부재:** `/send`는 route/method 확인 뒤 `readJson`을 호출하고 error를 400으로 매핑한다(`src/adapters/claude/channel-server.ts:557-579`). `readJson`은 모든 chunks를 배열에 저장한 뒤 `Buffer.concat`/JSON parse하며 byte count, `Content-Length`, streaming threshold, 413 경로가 없다(`src/adapters/claude/channel-server.ts:718-725`). 따라서 malformed/schema-invalid body도 전부 읽은 뒤 400이고 oversized valid body는 메모리 한계 전까지 parse/notification 경로로 간다. HTTP tests는 port selection/collision과 정상 canonical POST만 검증한다(`tests/unit/adapters/claude-channel.test.ts:1419-1498`); oversized body rejection은 없다.
