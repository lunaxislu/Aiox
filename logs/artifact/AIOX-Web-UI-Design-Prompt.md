# AIOX 운영 Web UI 디자인 프롬프트 (Stage 6, 1차: workspace 화면)

아래 전체를 클로드 앱에 붙여넣는다. 설정 화면은 2차 프롬프트로 분리한다.

---

AIOX라는 로컬 개발자 도구의 운영 Web UI를 **동작하는 HTML 프로토타입**으로 만들어 주세요.
단일 HTML 아티팩트 하나로, 드래그·분할·탭 전환이 실제로 동작해야 합니다.

## 제품 배경 (설계에 필요한 만큼만)

AIOX는 개발자 로컬 머신에서 Claude Code와 Codex의 **실제 터미널 UI(TUI)**를 실행하고,
여러 agent를 서로 연결해 협업시키는 도구입니다. 브라우저에서 그 터미널들을 보고 배치합니다.

중요: 모델 선택, slash command, 승인 다이얼로그 같은 vendor UX는 **터미널 안에서** 벌어집니다.
이 화면은 그걸 복제하지 않습니다. 이 화면이 하는 일은 세 가지뿐입니다 —
터미널을 담는 그릇, 어떤 agent가 무슨 상태인지, 알림.

감각적 참고: cmux, Ghostty, VS Code 통합 터미널. 개발자 도구, 고밀도, dark-first.
나중에 React + Tailwind + shadcn/ui로 구현할 예정입니다.

## 전체 레이아웃

**사이드바가 전체 높이를 차지하고, 그 오른쪽에 헤더 바 + 메인이 놓입니다.**
(shadcn의 SidebarProvider + SidebarInset 구조)

```
┌────────────────┬──────────────────────────────────────────────────┐
│ AIOX           │ ◧ development · ~/projects/app · feat/login      │ ≤40px
│                │                      [Search… ⌘K]   🔔   ☀︎     │
├────────────────┼──────────────────────────────────────────────────┤
│ WORKSPACES   + │  ┌────────────────┬──────────────────┐           │
│   main         │  │[Claude][sh][+] │ [Codex][Rev][+]  │           │
│   scratch      │  │────────────────┼──────────────────┤           │
│ NETWORKS       │  │                │                  │           │
│   dev          │  │    terminal    │     terminal     │           │
│ HOSTS          │  │                │                  │           │
│   development  │  └────────────────┴──────────────────┘           │
└────────────────┴──────────────────────────────────────────────────┘
```

헤더 바는 한 줄이고 40px 이하입니다. 위 그림은 내용을 보여주려 두 줄로 그렸을 뿐입니다.

**사이드바와 메인 영역은 붙어 있습니다(flush).** 메인을 라운드 카드로 띄우는 inset 형태는
쓰지 마세요 — 터미널은 여백이 곧 정보 손실이고, pane 경계 드래그 핸들과 모서리가 겹칩니다.

### 사이드바 (전체 높이)

맨 위에 AIOX 로고/워드마크. 그 아래 세 섹션이 이어집니다.
세 섹션은 **전부 같은 종류(workspace)**이고 생기는 방법만 다릅니다:

- WORKSPACES — 사용자가 Web에서 직접 만듦. 섹션 헤더에 `+` 버튼. 이름 변경·삭제 가능
- NETWORKS   — CLI로만 생김(`aiox network create dev`). **`+` 버튼 없음**
- HOSTS      — CLI로만 생김(`aiox host run`). **`+` 버튼 없음**

`+`는 이 한 곳에만 두세요. pane 안의 `[+]`는 터미널·분할을 만드는 별개 버튼이라,
다른 곳에도 `+`를 두면 같은 기호가 두 가지를 뜻하게 됩니다.

셋 다 클릭하면 같은 형태의 workspace 화면으로 전환됩니다.
workspace 화면 = pane 트리이고, pane마다 **독립된 탭바**를 가집니다.

#### 사이드바 표시·크기 동작

- 토글(⌘B, 또는 헤더 바 왼쪽 버튼)로 **완전히 숨겨집니다.** 숨기면 메인이 가로 폭을
  전부 차지합니다. 아이콘만 남는 축소(rail) 모드는 쓰지 마세요
- 오른쪽 경계를 마우스로 드래그해 너비를 조절합니다. 기본 240px, **최소 180px, 최대 400px**
- 최소 너비에 닿으면 **거기서 멈춥니다.** 더 끌어도 자동으로 숨겨지지 않습니다
- 숨긴 상태에서도 헤더 바의 토글 버튼은 계속 보여야 합니다
- 조절한 너비는 기억됩니다

### 헤더 바 (메인 위, workspace 헤더 성격)

왼쪽부터:

- 사이드바 토글 (⌘B). **토글은 여기 한 곳에만** — 사이드바를 접어도 계속 보여야 하니까요
- 현재 workspace 이름과 맥락. workspace 종류에 따라 내용이 다릅니다:
  - Host → 이름 · 작업 경로 · worktree 브랜치 (있으면)
  - Network → 이름 · 멤버 수
  - Workspace → 이름만
- 오른쪽: 검색창(클릭하거나 ⌘K로 커맨드 팔레트), 알림 벨(미확인 배지), 테마 토글(dark/light)
- 연결 상태는 **평소에 표시하지 않습니다.** daemon 연결이 끊겼을 때만 이 바에 경고가
  나타나게 하세요. 늘 켜져 있는 녹색 점은 두지 마세요

## 반드시 동작해야 하는 상호작용

1. 사이드바 항목 클릭 → workspace 전환. 각 workspace는 자기 pane 배치·탭 순서·선택을 기억하고,
   헤더 바의 맥락 표시도 함께 바뀜
2. pane의 `[+]` → 드롭다운: New shell (⌘T) / Split right (⌘D) / Split down (⌘⇧D)
3. 탭 드래그 — 네 가지 결과를 모두 구분:
   - 같은 탭바 안 → 순서 변경 (삽입선 표시)
   - 다른 pane의 탭바 → 그 pane으로 이동
   - pane 가장자리(상·하·좌·우) → **새 분할 생성**
   - pane 중앙 → 그 pane의 탭으로 합치기

   드롭 전에 들어갈 자리를 반투명 오버레이로 미리 보여줄 것.
   가장자리 존 두께는 디버그 패널에서 조절 가능하게(기본 pane의 20%)
4. pane 경계 드래그 → 리사이즈. hover 시 핸들이 드러남
5. 마지막 탭을 빼서 빈 pane이 되면 → 인접 pane이 자리를 채우며 병합
6. 포커스 — 활성 pane은 테두리 강조, 비활성은 약하게. 터미널 본문 색은 건드리지 않음
7. 탭 닫기 `×`
8. 병합할 게 없어 workspace가 비면 → 탭바와 `[+]`만 남은 빈 pane
9. 알림 벨 → 드롭다운 목록. 항목 클릭하면 해당 agent가 있는 workspace·pane·탭으로 이동 + 읽음 처리
10. 사이드바 토글·너비 조절 (위 「사이드바 표시·크기 동작」대로)
11. **커맨드 팔레트 (⌘K)** — 검색창 클릭으로도 열림:
    - workspace·터미널·agent 이름으로 검색해서 선택하면 그곳으로 점프
    - 명령도 함께 검색됨: New shell, Split right, Split down, Toggle theme, Toggle sidebar
    - 타이핑하면 두 종류가 섹션으로 나뉘어 필터링되고, ↑↓로 이동, Enter로 실행, Esc로 닫힘

## 터미널 내용

실제 구현은 xterm이 담당하므로 프로토타입에서는 **가짜 텍스트**입니다. 단 진짜처럼 보여야 합니다.

- shell 탭: 프롬프트 + 명령 기록 몇 줄 (`git status`, `pnpm build`,
  `aiox agent run claude --network dev` 등)
- agent 탭: Claude Code / Codex TUI처럼 보이는 가짜 출력 — 박스 드로잉 문자, 작업 진행 표시,
  도구 호출 로그
- 등폭 폰트. 터미널 배경은 주변 chrome과 같거나 아주 약간 더 어둡게

## 상태 (실제 값이므로 이름을 바꾸지 마세요)

agent 상태 5가지:
`aiox-preparing` `idle` `working` `awaiting-user` `failed`

- 탭에 상태 점(dot)으로 표시. 색은 각각 구분되게
- `awaiting-user`는 사용자가 TUI에서 직접 답해야 하는 상태 → **가장 눈에 띄어야 함**
- `failed`는 이유 문자열이 붙음 (예: `rate_limit`, `authentication_failed`)

터미널 종류 3가지:

- `shell` — 사용자가 명령을 치는 곳
- `agent` — vendor TUI가 도는 곳
- `external` — 외부 터미널(사용자의 Ghostty 등)에서 실행된 agent.
  AIOX가 소유한 화면이 아니라 **터미널 내용을 보여줄 수 없음**.
  이 탭을 선택하면 터미널 대신 안내를 표시:
  "This agent runs in an external terminal. AIOX cannot display its screen."
  + agent 이름과 현재 상태. 조작 버튼은 없음

## 비주얼

- **dark-first**. light 테마도 토글로 전환되게 (두 테마 다 완성도 있게)
- 색은 shadcn/ui 스타일의 CSS 변수 토큰으로 정의:
  `--background --foreground --card --muted --muted-foreground --border --accent --ring`,
  사이드바용 `--sidebar --sidebar-foreground --sidebar-border` 등.

- **UI 문구는 전부 영어**
- 데스크톱 우선(1280px 이상 기준). 모바일 대응 불필요

## 1. 사이드바 섹션을 아코디언으로 바꾸고, 섹션 개요 화면을 추가

사이드바의 WORKSPACES / NETWORKS / HOSTS 세 섹션을 접었다 펼 수 있는 아코디언으로 만듭니다.

- **섹션 헤더 클릭** → 아코디언이 펼쳐지고, 동시에 메인 영역에 그 섹션의 **카드 목록**이 표시됩니다
- **섹션 안의 항목 클릭** → 기존처럼 그 workspace 화면으로 들어갑니다

카드에 담을 내용:

| 섹션 | 카드 내용 |
| --- | --- |
| WORKSPACES | 이름, 터미널 개수 |
| NETWORKS | 이름, 멤버 수, route 요약 (누가 누구에게 보낼 수 있는지) |
| HOSTS | 이름, 작업 경로, worktree 브랜치(있으면), agent 개수와 상태 |

### 비어 있을 때의 화면

처음 실행하면 세 섹션이 전부 비어 있습니다. 각 섹션의 개요 화면에 아래 문구를 넣어 주세요.
**문구는 이 영문 그대로 쓰세요.**

WORKSPACES — 유일하게 화면에서 만들 수 있는 항목이고, 나머지 둘의 전제입니다:

```
Start here

A workspace is where your terminals live. Create one to run commands —
including the aiox commands that create networks and hosts.

[ New workspace ]
```

NETWORKS — CLI로만 생기므로 버튼 대신 복사 가능한 명령을 보여 줍니다:

```
No networks yet

Networks let agents talk to each other. Create one from a terminal:

  aiox network create dev                          [copy]
```

HOSTS — 같은 형식:

```
No hosts yet

A host runs a set of agents declared in aiox.yaml, all sharing one working directory.

  aiox host run --path ./aiox.yaml                 [copy]
```

세 개가 동시에 비어 있을 때 "Start here"만 제목 형식이 달라서 시선이 거기로 가야 합니다.
이게 의도이므로 나머지 둘의 "No ~ yet" 형식에 맞추지 마세요.

## 2. 설정 진입을 사이드바 맨 아래로

- 사이드바 최하단에 구분선을 두고 그 아래 `⚙ Settings` 항목을 둡니다(아코디언 바깥, 항상 바닥에 붙어 있음)
- 헤더 우측에는 검색·알림 벨·테마 토글만 남깁니다. 설정 아이콘을 헤더에 넣지 마세요
- 설정 화면 자체는 아직 만들지 않습니다. 클릭하면 "Settings — coming soon" 정도의 자리만 표시하세요
- 사이드바를 접으면 이 항목에 접근할 수 없으므로, **⌘K 커맨드 팔레트의 명령 목록에 `Settings`를 추가**해 주세요

## 3. 헤더 바의 토글과 맥락 텍스트를 구분

사이드바 토글(`◧`)과 그 오른쪽 workspace 맥락 텍스트(`main · workspace · 1 terminal`) 사이에
세로 구분선을 하나 넣어 주세요. 지금은 둘이 붙어 있어서 토글이 workspace 이름의 아이콘처럼
읽힙니다. 토글은 사이드바를 제어하는 전역 컨트롤이라 맥락 텍스트와 성격이 다릅니다.

## 기록 — 사용자가 클로드 앱에 직접 요청한 사항

아래는 이미 클로드 앱에 요청한 내용이다. 다시 붙여넣지 않고 이 파일의 계약으로만 유지한다.

- 사이드바 WORKSPACES 항목은 우클릭 컨텍스트 메뉴로 이름 변경·삭제를 할 수 있다.
- NETWORKS·HOSTS 항목에는 이름 변경·삭제를 제공하지 않는다. CLI가 소유하는 항목이기 때문이다.
- 사용자 Workspace는 터미널이 0개가 되어도 사라지지 않는다. 카드에 `0 terminals`로 남고
  화면은 빈 pane + `[+]`가 된다. 제거 경로는 우클릭 삭제 하나뿐이다.
- Workspace 삭제 시 안에 살아 있는 터미널이 있으면 확인 dialog를 띄운다. 종료될 터미널·agent를
  나열하고 버튼은 `Cancel` / `Stop and delete` 두 개다. 모든 터미널이 idle로 확인된 경우에만
  dialog 없이 삭제한다. busy이거나 idle을 판정할 수 없는 경우(Windows, shell integration이 없는
  shell, terminal.args 지정)는 판정 불가를 busy로 취급해 dialog를 띄운다. 이는 daemon stop의
  Windows 검사 생략과 구분되는 규칙이며, 근거는 "모르면 busy"라는 기존 원칙이다.
- `aiox agent run`을 `--network` 없이 실행하면 그 agent는 명령을 친 workspace에 그대로 나타난다.
  대상 network가 없으므로 이동할 곳도 없다.

## 4차 수정 지시 — 삭제 dialog 정합과 상태 판정 교정

1차 프로토타입(`AIOX Workspace.html`)을 실제로 실행해 검토한 결과다. 아래를 같은 대화에
이어서 붙여넣는다. 3차에서 요청했던 "디버그 패널에 dialog 토글"은 철회한다. 취소 버튼이
있으므로 우클릭 → Delete → Cancel로 확인할 수 있어 별도 토글이 필요 없다.

---

프로토타입을 실행해서 확인했습니다. 구조·문구·empty state·리사이즈는 의도대로 나왔습니다.
세 가지만 고쳐 주세요.

## 1. 살아 있는 agent는 상태와 무관하게 `running`입니다

지금 `busyOf`가 agent의 상태가 `idle`이면 `idle`을 돌려줍니다. 그러면 agent만 있는 workspace는
"전부 idle"로 판정돼 **dialog 없이 바로 삭제**됩니다. 이게 실제 동작과 어긋납니다.

AIOX 서버는 살아 있는 agent runtime이 하나라도 있으면 상태와 무관하게 종료를 막습니다.
vendor가 보고하는 `idle`은 "지금 턴이 돌고 있지 않다"는 뜻이지 "터미널이 한가하다"가 아닙니다.
그 터미널을 없애면 대화가 사라집니다.

→ **agent 터미널은 살아 있는 한 언제나 `running`으로 표시**해 주세요. `idle`은 shell에만
해당합니다.

## 2. `scratch`에 판정 불가 터미널을 하나 추가해 주세요

지금 픽스처로는 `status unknown` 행을 화면에서 볼 수가 없습니다. `main`은 전부 idle이라 dialog가
안 뜨고, `scratch`는 idle과 running뿐입니다. 판정 불가는 이 dialog가 존재하는 이유인데 정작
시연이 안 됩니다.

`scratch`에 idle 판정이 불가능한 shell을 하나 더 넣어 주세요. 삭제 dialog가 이렇게 나와야 합니다.

```
  • shell   · idle
  • zsh     · running
  • bash    · status unknown
```

## 3. dialog 기본 포커스를 `Cancel`에 둬 주세요

3차에서 요청했는데 빠졌습니다. 지금은 dialog가 열려도 아무 버튼에도 포커스가 없고, 시각적으로
두드러지는 쪽은 파괴적인 `Stop and delete`입니다. 열리는 순간 `Cancel`에 포커스가 가야 하고,
Tab이 dialog 밖으로 나가지 않아야 합니다. (Esc로 닫기는 이미 잘 동작합니다.)

## 4. external 탭에서 닫기(`×`) 버튼을 빼 주세요

외부 터미널에서 실행된 agent(`EXT` 배지가 붙은 탭)는 AIOX가 소유한 프로세스가 아니라서
종료시킬 수 없습니다. 그런데 지금 닫기 버튼이 달려 있습니다.

이 탭은 외부 agent가 살아 있는 동안만 존재하고, 그 agent가 끝나면 저절로 사라집니다. 사용자가
개입할 자리가 없으므로 `×`를 표시하지 마세요. 탭 자체는 그대로 클릭·선택 가능합니다.

## 5. 탭 닫기(`×`)에 확인 dialog를 붙여 주세요

owned 탭(`shell`, `agent`)의 `×`는 **터미널을 종료**합니다. 배치에서만 빼는 것이 아닙니다.

- 터미널이 idle임을 **확인한 경우에만** dialog 없이 바로 닫습니다
- 실행 중임을 확인했거나, **바쁜지 판단할 수 없으면** dialog를 띄웁니다 (모르면 물어봅니다)

dialog는 단순하게 갑니다. 탭 이름도, 터미널 목록도, 상태 표시도 넣지 마세요.

```
Close this tab?

Closing stops the terminal. It may still be running — AIOX cannot always
tell whether a terminal is busy.

            [ Cancel ]  [ Close and stop ]
```

- 기본 포커스는 `Cancel`, `Close and stop`은 destructive 스타일
- Esc로 닫으면 취소
- external 탭은 `×`가 없으므로 해당 없습니다
- WORKSPACES·NETWORKS·HOSTS 어느 섹션의 workspace든 규칙은 같습니다. network나 host의
  탭이라고 해서 다르게 처리하지 마세요
- 마지막 탭을 닫으면 지금처럼 빈 pane + `[+]`가 됩니다. network·host에서도 마찬가지이며
  shell을 자동으로 새로 만들지 마세요

참고로 브라우저나 브라우저 탭을 닫는 것은 이것과 다릅니다. 그때는 아무것도 종료되지 않고
재방문하면 화면이 복귀합니다. 종료는 `×`를 누른 경우에만 일어납니다.

## 6. (사소) 디버그 패널이 우하단 pane의 status bar를 가립니다

접었을 때도 가립니다. 패널을 조금 위로 올리거나, 접었을 때는 헤더만 남기고 더 작게 만들어
주세요.

## 5차 수정 지시 — external agent 배치, 카드 내용, 빈 화면

4차와 별개로 대화에서 확정한 내용이다. 아래를 같은 대화에 이어서 붙여넣는다.
`standalone`은 이 제품이 이미 쓰는 단어로, network·host 어디에도 속하지 않은 실행을 뜻한다
(`docs/specs/aiox-runtime.md:59`, `plans/aiox-tui-product-rebuild.md:13`).

---

## 1. external agent는 탭이 아니라 카드에서만 보여 주세요

지금 외부 터미널에서 실행된 agent가 workspace에 탭으로 들어가 있습니다. 눌러도 "화면을 보여줄
수 없다"만 나오는 죽은 탭이라 탭바 자리만 차지합니다.

- 탭 목록에서 빼 주세요
- pane 본문의 external 안내 화면(`This agent runs in an external terminal…`)도 같이 없앱니다

대신 섹션 카드가 이 정보를 갖습니다. 보여줄 수 있는 게 이름과 상태뿐이라, 카드가 그 크기에 맞는
자리입니다.

## 2. 카드에 agent 목록을 넣고 개수를 두 갈래로 나눠 주세요

지금 NETWORKS 카드는 route만 보여줍니다. agent 목록을 추가해 주세요. route 목록은 그대로 둡니다.
"누가 있나"와 "누가 누구에게 말할 수 있나"는 다른 정보라 둘 다 필요합니다.

개수는 그 network/host에 **속한** agent와, 패널에 있지만 아무 데도 속하지 않은
agent(standalone)를 나눠서 표시합니다.

```
dev                                    3 agents · 1 standalone

  ● claude      ● codex      ○ reviewer EXT
  ─────────────────────────────────────────
  ● helper

  claude → codex
  codex → reviewer
  reviewer → claude
```

- 구분선 위가 소속 agent, 아래가 standalone입니다. 구분선이 무거워 보이면 여백만으로 나눠도 됩니다
- standalone이 하나도 없으면 `3 agents`만 쓰고 뒤쪽은 표시하지 않습니다. `0 standalone`은 쓰지 마세요
- `EXT`는 외부 터미널 실행 표시입니다. standalone 여부와 별개이므로 둘 다 붙을 수 있습니다
- HOSTS 카드도 같은 규칙입니다

이렇게 하면 헤더에 `3 agents`라고 떠 있는데 탭은 2개인 상황을 카드가 설명해 줍니다.

## 3. 섹션이 비었을 때 문구를 사용법으로 바꿔 주세요

지금 NETWORKS 빈 화면은 `aiox network create dev` 한 줄만 보여줍니다. 그것만 치면 빈 network가
생기고 화면은 여전히 비어 있어서, 사용자가 "만들었는데 왜 아무것도 없지"가 됩니다. 전체 흐름을
보여줘야 합니다. `[copy]` 버튼은 빼 주세요. 줄이 여러 개면 무엇을 복사하는지 모호하고, 사용자는
어차피 터미널 앞에 앉아 있습니다.

NETWORKS:

```
No networks yet

A network lets agents send messages to each other. Create one, then start
agents in it:

  aiox network create dev
  aiox agent run claude --network dev
  aiox agent run codex --network dev
```

HOSTS는 `aiox.yaml`이 agent를 이미 선언하고 있어서 한 번에 다 뜹니다. 단계를 억지로 늘리지 말고
왜 한 줄이면 되는지를 문구가 말하게 해 주세요:

```
No hosts yet

A host runs a set of agents declared in aiox.yaml, all sharing one working
directory. The file lists the agents, so one command starts all of them:

  aiox host run --path ./aiox.yaml
```

WORKSPACES의 `Start here`는 지금 그대로 둡니다. 화면에서 만들 수 있는 유일한 항목이라 명령이
아니라 버튼이 맞습니다.

## 4. workspace 안이 비었을 때도 맥락에 맞게 바꿔 주세요

3번과 다른 화면입니다. 3번은 "섹션에 항목이 하나도 없다"이고, 이건 "항목은 있는데 그 안에
터미널이 없다"입니다. 지금은 어느 workspace든 `Empty pane — use + to start a terminal` 하나로
같아서 network나 host에서는 도움이 안 됩니다. `[+]`는 그대로 둡니다.

**사용자가 `+`로 만든 패널** — 어느 섹션에 있든 같습니다. 이 패널은 특정 network나 host에
묶여 있지 않아서 추천할 명령이 없습니다. 억지로 명령을 보여주지 말고 가볍게 권하기만 하세요.

```
No terminals here

Open one with + and run something fun.
```

**CLI가 만든 Network 패널** — 이름은 실제 network 이름을 넣어 주세요:

```
No terminals in dev

  aiox agent run claude --network dev
```

**CLI가 만든 Host 패널**:

```
No terminals in development

  aiox host agent start development <agent>
```

셋 다 3번의 섹션 빈 화면보다 작고 조용해야 합니다. 그건 "아직 시작 안 했다"이고 이건 "여기가
비었다"라서 무게가 다릅니다. 특히 첫 번째 문구는 자주 보게 되는 화면이므로 농담을 세게 넣지
마세요.

## 5. WORKSPACES 카드에도 agent 목록을 넣어 주세요

지금 `main · 1 terminal`처럼 개수만 나옵니다. 사용자 workspace에서도 `aiox agent run claude`로
agent를 띄울 수 있는데 카드에 아무 흔적이 없습니다. 2번과 같은 형식으로 이름 + 상태 점을
넣어 주세요.

```
main                                   2 terminals

  ● claude      ○ codex
```

agent가 없는 workspace는 지금처럼 개수만 나오면 됩니다.

## 6. NETWORKS·HOSTS 섹션 헤더에도 `+`를 달아 주세요

지금 `+`는 WORKSPACES 헤더에만 있습니다. 세 섹션 모두에 두고, 누르면 그 섹션 아래에 새 패널이
하나 생깁니다. 만들어진 패널은 클릭하면 지금과 똑같은 workspace 화면(pane 분할 + pane별 탭바)을
열고, 이름은 `untitled-1`처럼 붙은 뒤 바로 편집 상태가 됩니다. WORKSPACES의 `+`와 동작이 같습니다.

우클릭 메뉴는 **누가 만들었는지**로 갈립니다.

- `+`로 만든 패널 → `Rename` / `Delete` 둘 다 제공합니다. 어느 섹션에 있든 같습니다
- CLI가 만든 패널(`dev`, `development`) → 우클릭 메뉴를 주지 마세요. `aiox network create`,
  `aiox host run`이 소유하는 항목이라 화면에서 이름을 바꾸거나 지울 수 없습니다

같은 섹션 안에서 둘이 섞이므로 어느 것이 CLI 소유인지 알 수 있으면 좋겠습니다. 다만 배지를 새로
만들지는 마세요. 우클릭했을 때 메뉴가 안 뜨는 것으로 충분합니다.

## 6차 수정 지시 — 2차 프로토타입 검토 결과

4차·5차가 모두 반영된 것을 확인했다. 남은 두 가지만 고친다.

---

## 1. CLI가 만든 패널을 우클릭하면 브라우저 기본 메뉴가 뜹니다

5차 6번대로 CLI 패널(`dev`, `development`)에는 AIOX 메뉴가 안 뜨는데, 대신 브라우저의 기본
우클릭 메뉴(`뒤로 가기`, `새로고침`, `다른 이름으로 저장`…)가 뜹니다. 아무것도 안 뜨는 것보다
나쁩니다.

핸들러를 `null`로 두지 말고, 항상 `preventDefault()`는 호출하되 메뉴만 열지 마세요.
사이드바 항목과 섹션 카드 둘 다 해당합니다.

## 2. standalone agent가 카드에만 있고 패널에는 없습니다

`dev` 카드는 `3 agents · 1 standalone`에 `NOT IN DEV / ● helper`까지 잘 나옵니다. 그런데 `dev`를
열면 `helper` 탭이 없습니다. external인 `reviewer`와 같은 취급을 받고 있는데, 이 둘은 다릅니다.

- **external agent** — AIOX가 띄운 터미널이 아니라서 화면이 없습니다. 카드에만 나옵니다. (5차 1번)
- **standalone agent** — AIOX가 띄운 평범한 agent입니다. 화면이 있고 탭이 있습니다. 다만
  `--network dev` 없이 실행돼서 network의 멤버가 아닐 뿐입니다

즉 standalone은 **패널 안에 탭으로 있으면서** 카드에서 구분선 아래로 내려가는 agent입니다.
`3 agents · 1 standalone`을 보고 패널을 열었을 때 helper가 탭으로 있어야 카드의 구분이 설명됩니다.

- `helper`를 `dev` 패널의 pane 중 하나에 탭으로 넣어 주세요
- 카드가 패널에서 agent를 모을 때 standalone으로 지정된 것은 위쪽 목록에서 빼 주세요. 안 그러면
  같은 agent가 구분선 위아래에 두 번 나옵니다

**카드에 나오는 세 부류를 정리하면:**

| | 패널에 탭이 | 카드 구분선 | 개수 |
|---|---|---|---|
| network 멤버, 터미널이 이 패널에 있음 (`claude`, `codex`) | 있음 | 위 | `agents` |
| network 멤버, 터미널이 없거나 다른 곳에 있음 (`reviewer` EXT) | 없음 | 위 | `agents` |
| 이 패널의 agent인데 멤버가 아님 (`helper`) | **있음** | 아래 | `standalone` |

**덤으로 fixture 하나만 봐 주세요.** `main` workspace의 shell 화면에
`aiox agent run claude --network dev` → `started agent claude (pid 48213) → network dev`가 찍혀
있고, 그 결과로 `main` 패널에 `claude` 탭이 있습니다. 그런데 `dev` 카드에는 이 claude가 없습니다.
위 표의 두 번째 줄이 바로 이 경우입니다. `dev` 카드 위쪽 목록에 넣어 주면 "멤버지만 터미널은 다른
패널에 있다"가 한 화면에서 설명됩니다.

# AIOX 운영 Web UI 디자인 프롬프트 (Stage 6, 2차: 설정 화면)

아래 전체를 클로드 앱에 붙여넣는다. 기존 프로토타입의 `⚙ Settings` 자리를 채우는 작업이다.

---

기존 AIOX 프로토타입에 **설정 화면**을 추가해 주세요. 지금은 `⚙ Settings`를 누르면
"Settings — coming soon"만 뜹니다. 그 자리를 채웁니다.

## 이 설정이 무엇인가

사용자 홈의 **전역 설정 파일 하나**(`~/.aiox/config.json`)를 편집하는 화면입니다.
프로젝트별 설정은 없습니다. 모든 workspace, Host, standalone 실행에 같은 값이 적용됩니다.

사용자가 그 파일을 직접 열어 고칠 수도 있고, 그때도 같은 검증을 통과해야 적용됩니다.
그래서 이 화면은 "파일의 또 다른 입구"이며, 파일에 없는 개념을 만들어내지 않습니다.

## 화면 구조

설정은 **메인 영역을 차지하는 전체 화면**입니다. 사이드바는 그대로 남고 `⚙ Settings`가
선택 상태가 됩니다. 모달·오버레이로 띄우지 마세요 — 값이 많고 터미널을 보면서 고칠 일이
없습니다.

```
┌────────────────┬──────────────────────────────────────────────────┐
│ AIOX           │ ◧ │ Settings                       ~/.aiox/config.json │
├────────────────┼──────────────────────────────────────────────────┤
│ WORKSPACES   + │ Terminal      Font family  [ SF Mono         ]   │
│   main         │ Keybindings   Font size    [ 13 ]               │
│ NETWORKS       │ Appearance    Theme        [ Dark ▾ ] [Customize]│
│   dev          │ Server        ────────────────────────────────── │
│ HOSTS          │ Host layout   Shell        [ /bin/zsh        ]   │
│   development  │               Arguments    [ -l              ]   │
│ ────────────── │               Directory    [ ~/projects      ]   │
│ ⚙ Settings     │                                                  │
└────────────────┴──────────────────────────────────────────────────┘
```

왼쪽에 섹션 목록(세로), 오른쪽에 그 섹션의 필드. 섹션 전환은 스크롤이 아니라 목록 클릭입니다.
헤더 바 오른쪽에 실제 파일 경로를 흐리게 보여 주세요 — 어디가 바뀌는지 알 수 있게.

## 섹션과 필드

**아래 필드가 전부입니다. 없는 항목을 추가하지 마세요.** 각 필드의 검증 규칙은 실제 구현에서
쓰는 것과 같습니다.

### Terminal

| 필드 | 입력 | 규칙 |
| --- | --- | --- |
| Font family | 텍스트 | 비울 수 없음 |
| Font size | 숫자 | 0보다 큰 수 |
| Theme | 색 편집 | `background`·`foreground`·`cursor`와 ANSI 16색 |
| Shell | 텍스트 | 실행 파일 이름 또는 경로. 비우면 OS 기본값 |
| Arguments | 문자열 목록 | 인자를 하나씩 추가·삭제 (한 줄에 공백으로 나열하지 마세요) |
| Working directory | 텍스트 | 경로. 비우면 daemon 작업 경로 |

- Shell을 비웠을 때의 기본값을 placeholder로 보여 주세요: macOS/Linux는 `$SHELL` 또는
  `/bin/bash`, Windows는 `%COMSPEC%` 또는 `cmd.exe`
- **Shell·Arguments·Directory는 "새로 만드는 shell"에만 적용됩니다.** 이미 열려 있는 터미널은
  바뀌지 않습니다. 이 셋을 묶어 그 아래에 한 줄로 명시해 주세요
- Font family/size는 반대로 **열려 있는 모든 터미널에 즉시 적용**되고 터미널 크기가 다시
  계산됩니다
- Theme 색은 기본값 + `Customize`로 펼치는 색 목록. 16색을 처음부터 다 펼쳐 두지 마세요

### Keybindings

11개 항목입니다. 각 행은 `기능 — 현재 키 — [Change]`이고, 기본값에서 바뀐 행에만
`Reset` 버튼과 `edited` 표시가 붙습니다.

```
New shell              ⌘⇧S                      [Change]
Split right            ⌘D                       [Change]
Split down             ⌘⇧D                      [Change]
Switch tab             ⌘1…⌘8, ⌘9 = last tab     [Change]
Close tab              ⌘⇧X                      [Change]
Focus left/down/up/right  ⌘⌥H ⌘⌥J ⌘⌥K ⌘⌥L      [Change]
Zoom pane / restore    ⌘⇧M                      [Change]
Equalize sizes         ⌘⇧=                      [Change]
Flash current pane     ⌘⇧P                      [Change]
Toggle sidebar         ⌘B              edited   [Change] [Reset]
Open command palette   ⌘K                       [Change]
```

`Change`를 누르면 그 행이 `Press keys…` 상태가 되고 다음 키 조합을 받습니다.
**여기서 반드시 다뤄야 하는 실패가 있습니다.**

- 브라우저나 OS가 먼저 가로채는 조합(`⌘T`, `⌘⇧N`, `⌘⇧3`…)은 **이 화면에 도달하지 않습니다.**
  그래서 사용자가 눌러도 아무 일도 일어나지 않고, 화면이 `Press keys…`에 멈춰 있습니다
- 2초쯤 기다렸다가 `That combination is reserved by your browser or OS. Try another.`를
  같은 자리에 보여 주세요. 조용히 멈춰 있으면 사용자는 화면이 고장난 줄 압니다
- 이미 다른 기능이 쓰는 조합을 누르면 `Already used by "Split right"`와 함께 그 행으로
  보내는 링크를 보여 주세요. 자동으로 빼앗지 마세요
- `Esc`로 취소

기본키는 제품이 제공하고 **바꾼 것만 파일에 저장됩니다.** 그래서 `edited` 표시와 `Reset`이
의미가 있습니다. 섹션 맨 아래에 `Reset all to defaults`를 하나 두세요.

### Appearance

| 필드 | 입력 |
| --- | --- |
| Theme | `System` / `Light` / `Dark` |
| Language | `한국어` / `English` |

- 이 Theme은 **AIOX 화면 색**이고 Terminal 섹션의 Theme(터미널 본문 색)과 다릅니다.
  두 섹션 각각에 한 줄로 그 구분을 적어 주세요
- `System`은 OS 설정을 따르고 OS에서 바뀌면 같이 바뀝니다

### Server

| 필드 | 입력 | 규칙 |
| --- | --- | --- |
| Daemon port | 숫자 | 1–65535 정수, 기본 4500 |
| Web port | 숫자 | 1–65535 정수, 기본 4501 |
| Message retention | 숫자(일) | 1 이상 정수, 기본 30 |

- 두 포트는 **같을 수 없습니다.** 같게 만들면 즉시 인라인 오류
- 포트는 저장돼도 **지금 실행 중인 daemon에는 적용되지 않습니다.** 저장 후 그 두 필드 아래에
  `Saved — applies on next daemon start`를 보여 주세요. 다른 필드와 시각적으로 구분되어야
  합니다
- Message retention은 요청이 끝난 메시지 이력을 며칠 보관하는지입니다

### Host layout

`aiox host run`으로 만든 Host가 처음 열릴 때의 pane 배치 기본값입니다.

- Preset: `auto` / `left-main` / `top-main` / `grid`
- `grid`를 골랐을 때만 Columns·Rows 입력이 나타납니다. 다른 preset에서는 숨기세요
  (값이 있는 채로 비활성만 해 두면 저장 시 오류가 납니다)
- 각 preset을 작은 그림으로 보여 주세요. 이름만으로는 무엇이 다른지 알 수 없습니다

## 반드시 동작해야 하는 것

1. **저장은 명시적입니다.** 화면 아래에 `Save` / `Discard`를 고정하고, 바뀐 필드 수를 같이
   보여 주세요(`3 changes`). 타이핑마다 저장하지 마세요 — 잘못된 중간 값이 파일에 들어갑니다
2. **검증 실패 시 저장이 일어나지 않고 마지막 유효 값이 그대로 유지됩니다.** 오류는 그 필드
   옆 인라인으로. 상단 배너 하나로 묶지 마세요
3. **파일이 외부에서 바뀌면** 상단에 `This file changed on disk. [Reload]`를 띄우세요.
   편집 중인 값을 말없이 덮어쓰지 마세요
4. **daemon이 꺼져 있어도 편집·저장은 됩니다.** 그 경우 헤더에 `daemon not running — saved values load on next start`를 보여 주세요
5. 섹션을 옮겨도 저장 안 한 값은 유지됩니다. 다른 화면(workspace)으로 나가려 할 때만
   `Discard changes?`를 묻습니다

## 넣지 말 것

- **사이드바 너비 입력** — 경계를 드래그하면 자동 저장됩니다. 숫자로 또 받지 마세요
- **daemon 재시작 버튼** — 설정 저장이 daemon을 재시작하거나 agent를 종료하지 않습니다
- **vendor 설정** — 모델 선택, 승인 정책, MCP 같은 Claude/Codex 설정은 터미널 안에서 합니다
- **계정·로그인·원격 동기화·설정 내보내기** — 로컬 파일 하나가 전부입니다
- **프로젝트별 override** — 없습니다
- **Windows/Linux 키 표시** — 아직 확정되지 않았습니다. macOS 키만 보여 주세요
- 검색·필터 — 필드가 20개뿐입니다

## 같이 고쳐 주세요 (기존 화면)

pane의 `[+]` 드롭다운이 `New shell (⌘T)`로 표시되는데, `⌘T`는 Chrome 새 탭이라 **이 화면에
도달하지 않습니다.** 실제로 눌러 확인했습니다. `New shell (⌘⇧S)`로 바꿔 주세요.

같은 드롭다운의 `Split right (⌘D)`·`Split down (⌘⇧D)`와 사이드바 토글 `⌘B`, 검색 `⌘K`는
그대로 두세요. 이 넷은 확인 결과 문제가 없었습니다.

## 7차 수정 지시 — 설정 화면 검토 결과와 저장 정책 확정

아래 전체를 클로드 앱에 붙여넣는다. 1번은 앞선 지시가 틀렸던 것을 취소하는 항목이다.

---

## 1. 키 재지정의 예약키 안내를 취소하고 상시 힌트로 바꿔 주세요

앞서 "2초쯤 기다렸다가 `That combination is reserved by your browser or OS`를 보여 주세요"라고
요청했는데, **그 요구가 잘못됐습니다.** 지금 `Change`를 누르고 아무 키도 누르지 않아도 그 문구가
뜹니다.

페이지는 "사용자가 아직 아무 키도 안 눌렀다"와 "눌렀지만 브라우저가 가로채서 도달하지 않았다"를
구분할 수 없습니다. 둘 다 `keydown`이 오지 않는 것으로 똑같이 보입니다. 그래서 시간이 지났다는
이유로 예약이라고 단정하면 사실이 아닌 안내가 됩니다.

타임아웃 안내를 **없애고**, 대신 캡처를 시작하는 순간부터 그 자리에 중립적인 힌트를 계속 보여
주세요.

```
New shell    [ Press a combination…            ]    Change
             Keys your browser or OS reserves (⌘T, ⌘⇧N, ⌘⇧3…)
             never reach this page. Esc cancels.
```

이렇게 하면 사용자가 예약키를 눌러 아무 일도 일어나지 않아도 이유가 이미 화면에 있습니다.
추측해서 알려 주는 것보다 정확합니다. 충돌 안내(`Already used by "Split right"`)는 실제로 키가
도달했을 때만 뜨는 것이므로 지금 그대로 두세요.

## 2. `Discard changes?` dialog에 기본 포커스가 없습니다

이 dialog를 띄운 뒤 `document.activeElement`가 `body`입니다. 4차에서 두 dialog(workspace 삭제,
탭 닫기)의 기본 포커스를 안전한 쪽에 두기로 했는데 이 dialog에는 적용되지 않았습니다.

`Keep editing`에 포커스를 주세요. Enter로 편집을 계속하고 Esc로도 닫히는 것이 안전한 기본값입니다.
`Discard`가 빨간 버튼이라 시선이 거기로 가는데 포커스까지 없으면 키보드로는 아무 것도 못 합니다.

## 3. `Open command palette` 행을 추가해 주세요

keybindings 목록이 10개인데 11개여야 합니다. 검색·커맨드 팔레트를 여는 `⌘K`가 빠졌습니다.
`Toggle sidebar` 아래에 넣어 주세요.

```
Open command palette   ⌘K                       [Change]
```

`⌘K`는 브라우저 주소창 검색 자리이지만 페이지가 가져올 수 있는 키로 판단했습니다. 헤더 바의
검색창에 표시된 `⌘K`도 그대로 둡니다.

## 4. Appearance의 Theme·Language도 파일에 저장됩니다

정책이 확정됐습니다. 이 두 값은 브라우저 저장소가 아니라 **다른 모든 설정과 같은
`~/.aiox/config.json`에 들어갑니다.** 그래서:

- 두 값을 바꾸면 **다른 필드와 똑같이 변경 카운트에 들어가고 `Save`를 눌러야 파일에 기록됩니다**
- 단 색과 언어는 눈으로 보고 골라야 하므로, 누르는 **즉시 화면에 미리보기로 적용**해 주세요
- `Revert`나 `Discard`를 하면 미리보기도 원래대로 되돌아가야 합니다

즉 "즉시 보이지만 아직 저장되지 않은" 상태가 있습니다. 미리보기 중임이 드러나야 하니 그 두 필드
옆에 `Preview — not saved yet` 정도를 붙여 주세요.

## 5. 저장하려는데 파일이 그사이 바뀐 경우를 다뤄 주세요

이 제품은 파일을 감시하지 않기로 했습니다. 설정 화면을 **열 때**와 **저장할 때**만 파일을
읽습니다. 그래서 편집 중에 누가 파일을 고쳤는지는 저장하는 순간에야 알 수 있습니다.

`Save`를 눌렀을 때 파일이 열었을 때와 달라져 있으면 **말없이 덮어쓰지 마세요.** dialog로 물어
주세요.

```
The file changed while you were editing.

Someone edited ~/.aiox/config.json after you opened this screen.

                      [ Keep my edits and overwrite ]  [ Discard mine and reload ]
```

기본 포커스는 `Discard mine and reload`에 두세요. 남의 변경을 날리는 쪽이 더 위험합니다.

디버그 패널의 `config.json changed on disk` 토글을 이 상황에도 연결해 주세요. 토글이 켜진 상태로
`Save`를 누르면 이 dialog가 뜨게 해 주세요. 상단 `This file changed on disk. Reload` 배너는 지금처럼
그대로 두시고, 그 배너는 화면을 열 때 발견한 경우입니다.

## 6. Font family에 미리보기와 등폭 경고를 붙여 주세요

터미널은 글자 격자라 등폭이 아닌 폰트를 넣으면 화면 정렬이 깨집니다. 그리고 이 머신에 설치되지
않은 폰트를 적으면 조용히 다른 폰트로 대체됩니다. 둘 다 저장 후에야 알게 되면 늦습니다.

입력란 아래에 그 폰트로 렌더한 짧은 미리보기 한 줄을 두세요. 정렬을 눈으로 볼 수 있는 내용이
좋습니다.

```
Font family  [ SF Mono                     ]
             ABCDEFGHIJ abcdefghij 0123456789
             |||||||||| |||||||||| ||||||||||
```

그 폰트가 등폭이 아니면(예: `i`와 `W`의 폭이 다르면) 미리보기 아래에
`This font is not monospaced — terminal columns will not line up.`을 경고로 보여 주세요.
저장을 막지는 마세요. 사용자가 알고도 쓰겠다면 그건 선택입니다.

## 7. (사소) Message retention에 기본값을 보여 주세요

현재 값이 `7`인데 제품 기본값은 30입니다. 화면만 보면 기본값이 무엇인지, 지금 값이 기본값인지
알 수 없습니다. 입력란 옆에 `default 30`을 흐리게 적어 주세요. Daemon port·Web port에도 같은
방식으로 `default 4500`·`default 4501`을 붙여 주세요.

## 8차 수정 지시 — 폰트 경고의 근거 수정과 기본값 복귀

아래 전체를 클로드 앱에 붙여넣는다. 7차 지시는 세 항목(1·2·5)까지 포함해 전부 반영된 것을
확인했다. 1번은 다시 앞선 지시가 틀렸던 것을 취소하는 항목이다.

## 1. 등폭 경고의 판정 방법을 고치고, "설치되지 않음" 안내는 취소해 주세요

지금 화면은 기본값 `SF Mono`에서 미리보기는 등폭으로 잘 렌더되는데 바로 아래에
`This font is not monospaced — terminal columns will not line up.` 경고가 같이 떠 있습니다.
같은 자리에서 두 안내가 서로를 부정합니다.

원인을 확인했습니다. 미리보기는 `"입력값", ui-monospace, monospace`로 렌더하고, 등폭 판정은
대체 폰트 없이 `"입력값"` 하나만으로 `i`와 `W`의 폭을 재고 있습니다. `SF Mono`는 CSS에서 이름으로
해석되지 않는 폰트라 판정 쪽은 비례 폰트로 떨어지고, 미리보기 쪽은 `ui-monospace`로 떨어집니다.
그래서 판정과 그림이 서로 다른 폰트를 보고 있습니다.

**판정을 미리보기와 똑같은 폰트 스택으로 재 주세요.** 터미널이 실제로 쓰게 될 스택 그대로
측정하면, 화면에 보이는 그림과 경고가 항상 같은 대상을 말합니다. 이렇게 하면 `Helvetica`나
`Times`처럼 정말 설치돼 있고 정말 비례인 폰트에서만 경고가 뜹니다. 이게 맞는 동작입니다.

그리고 6차에서 제가 요청한 **"이 머신에 설치되지 않은 폰트" 안내는 취소합니다.** 브라우저에서
그 판정이 불가능한 것을 확인했습니다. `document.fonts.check`는 이 머신에서 존재하지 않는 이름
(`"Totally Fake Font 123"`)에도 `true`를 돌려줍니다. 즉 그 문구는 실제로는 절대 뜨지 않는
죽은 코드이거나, 뜬다면 근거 없는 단정입니다. 7차 1번의 타임아웃 안내와 같은 종류의 잘못된
요구였습니다. `This font is not installed on this machine…` 줄은 지워 주세요.

설치 여부를 알려 주는 대신 미리보기가 그 역할을 합니다. 이름을 잘못 적으면 미리보기의 모양이
바뀌는 것으로 사용자가 압니다.

## 2. Font family와 Font size를 비우면 기본값으로 돌아가게 해 주세요

지금은 두 칸 중 하나라도 비우면 `Font family cannot be empty.` /
`Font size must be a number greater than 0.`이 뜨고 `Fix 1 field to save`로 저장이 막힙니다.
그래서 **한 번 값을 적으면 기본값으로 되돌릴 방법이 화면에 없습니다.** Keybindings에는
`Reset all to defaults`가 있는데 이쪽에는 없습니다.

이 제품의 저장 방식은 "기본값은 코드가 갖고, 파일에는 바꾼 것만 적는다"입니다. 그래서 빈 칸은
잘못된 값이 아니라 **"이 항목은 기본값을 쓴다"**는 뜻이어야 합니다. Shell·Arguments·Working
directory가 이미 `Leave empty for the OS default`로 그렇게 동작합니다. 두 폰트 칸도 같게
맞춰 주세요.

- 비우면 오류가 아니라 정상입니다. 저장을 막지 마세요
- 비워서 저장하면 그 항목은 파일에서 빠지고 내장 기본값이 적용됩니다
- 빈 칸에는 기본값이 무엇인지 placeholder로 보여 주세요

```
Font family  [ ui-monospace, Menlo, monospace ]   ← placeholder(회색). 비어 있으면 이 스택
Font size    [ 13 ]  default 13
```

기본값은 family `ui-monospace, Menlo, monospace`, size `13`입니다. Font size 옆에는 7차 7번과
같은 방식으로 `default 13`을 붙여 주세요.

이렇게 하면 1번에서 문제가 된 `SF Mono` 기본값도 같이 사라집니다. 첫 화면의 Font family는
값이 채워진 상태가 아니라 **비어 있고 placeholder만 보이는 상태**로 보여 주세요.

## 3. Language를 바꿨을 때 실제로 미리보기가 되게 해 주세요

`한국어`를 누르면 `Preview — not saved yet`은 뜨는데 화면 글자는 그대로 영어입니다. 지금은
미리보기가 없는데 미리보기 중이라고 말하고 있습니다.

전체 화면을 번역해 달라는 건 아닙니다. **설정 화면 자신의 글자만** 한국어로 바꿔 주세요.
왼쪽 섹션 이름, 필드 이름, 필드 아래 설명, 하단 바(`No changes` / `N changes` / `Revert` /
`Save`), 그리고 dialog 문구까지입니다. `English`로 돌리면 영어로 돌아옵니다.

이 범위면 미리보기가 사실이 되고, 동시에 한국어 글자 길이가 지금 레이아웃에 들어맞는지도
같이 보입니다. 한국어가 더 길어서 줄이 깨지는 곳이 있으면 그게 지금 알아야 할 정보입니다.

Keybindings의 키 표기(`⌘⇧S` 등)와 `~/.aiox/config.json` 같은 경로, 색 이름(`bright black` 등)은
번역하지 마세요.

## 9차 수정 지시 — 다국어 철회와 Settings 진입 위치

8차 3건은 `aiox-version4.html`에서 전부 반영을 확인했습니다. 등폭 판정이 미리보기와 같은
스택을 보고(`Helvetica`에서만 경고, `SF Mono`·`Menlo`에서는 경고 없음), 두 폰트 칸을 비우면
placeholder로 기본값이 보이며 오류 없이 저장되고, 한국어 전환이 설정 화면 전체에서 실제로
동작하며 레이아웃도 깨지지 않았습니다.

이번 두 건은 그 결과에 대한 결함 보고가 아니라 제품 결정이 바뀐 데 따른 것입니다.

## 1. 다국어를 제거하고 UI 문구는 영어로 고정해 주세요

8차 3번에서 요청한 한국어 미리보기 구현을 **철회합니다.** 잘못 만들어서가 아니라, 운영 Web에
다국어를 넣지 않기로 결정했기 때문입니다. 요청대로 동작하는 것을 확인한 뒤의 방향 변경입니다.

- Appearance 섹션에서 `Language` 행을 통째로 제거해 주세요
- 영어/한국어 문자열 테이블과 언어 전환 로직을 제거하고 UI 문구는 영어 하나만 남겨 주세요
- Appearance에는 `Theme`(System / Light / Dark)만 남습니다. 섹션은 그대로 유지해 주세요
- 하단 변경 카운트에서 Language가 빠지고, Theme의 `Preview — not saved yet`은 그대로입니다

헤더의 화면 제목이 `Settings`로 고정돼 있던 것도 이 변경으로 함께 정리됩니다.

## 2. Settings 진입을 헤더 오른쪽으로 옮겨 주세요

지금 Settings로 들어가는 클릭 경로는 사이드바 맨 아래 `⚙ Settings` 행 하나뿐입니다. 두 가지가
불편합니다. 화면 왼쪽 맨 아래 구석이라 이동 거리가 멀고, `⌘B`로 사이드바를 접으면 그 행이
사이드바와 함께 사라져 클릭으로 들어갈 방법이 아예 없어집니다.

- 사이드바 하단의 `⚙ Settings` 행을 제거해 주세요
- 헤더 오른쪽 알림(🔔)과 테마(☀) 사이에 톱니 아이콘을 두고 그 자리를 진입으로 써 주세요
- 커맨드 팔레트(`⌘K`)의 `Settings` 항목은 그대로 두세요

```
┌──────────────┬────────────────────────────────────────┐
│ ▪ AIOX       │ dev · network · 3 agents  🔍  🔔  ⚙  ☀ │
├──────────────┼────────────────────────────────────────┤
│ WORKSPACES  +│                                        │
│  main        │            pane / tabs                 │

```

알림·테마와 같은 앱 전역 도구 묶음이라 의미가 맞고, 사이드바를 접어도 진입이 남습니다.
사이드바 하단은 비워 두시고 다른 것으로 채우지 마세요. 설정 화면에 들어가 있는 동안에는
지금 사이드바 행이 그랬던 것처럼 톱니가 활성 상태로 보이게 해 주세요.

Settings 전용 단축키는 이번에 만들지 않습니다. 팔레트 경로가 이미 있고, 후보인 `⌘,`는 macOS
Chrome의 설정 자리라 실측이 필요합니다. Keybindings 목록은 11개 그대로입니다.

## 10차 수정 지시 — 창 폭에 따른 반응형 (사이드바·헤더·설정)

전제를 먼저 적습니다. 이 반응형의 목적은 폰 전용 화면을 만드는 것이 아니라 **데스크톱
브라우저 창을 줄였을 때** 화면이 깨지지 않게 하는 것입니다. 기준 형태는 지금의 넓은 화면이고,
거기서 좁아질 때의 동작만 더합니다.

**손대지 않을 것 — 터미널 영역.** pane 분할, pane별 탭바, xterm 본문은 창이 좁아져도 레이아웃을
바꾸지 않습니다. pane이 4개면 각 pane 폭이 그대로 1/4로 줄고 xterm이 그 크기에 맞춰 다시
맞춰질 뿐입니다. 좁다고 pane을 세로로 쌓거나, 분할을 자동으로 풀거나, 탭바를 드롭다운으로
바꾸지 마세요.

breakpoint는 ~~`760px`~~ → **12차에서 `768px`로 바꿨습니다.** `768px` 이상은 지금 형태 그대로이고, `360px`~`768px` 미만이
아래에서 말하는 좁은 폭 동작입니다. `360px` 미만은 대상이 아닙니다.

## 1. 사이드바 — 좁으면 오버레이 드로어

- 넓은 폭: 지금 그대로입니다. 240px 기본, 180~400 드래그 리사이즈, 메인과 flush
- 좁은 폭: 기본 닫힘. 헤더 왼쪽 햄버거나 `⌘B`로 열리고, 메인 **위에 덮는** 오버레이로 뜹니다.
  바깥을 누르거나 `Esc`를 누르면 닫히고, workspace를 고르면 닫힙니다
- 드로어일 때는 리사이즈 핸들을 숨기고 폭을 고정합니다(280px 초안)
- ~~드로어 **하단**에 알림(🔔)·설정(⚙)·테마(☀) 세 아이콘 줄을 둡니다~~ → **11차에서 드로어
  상단으로 변경했습니다.** 넓은 폭에서 헤더가 갖던 것들이며, 넓은 폭의 사이드바에는 두지
  않습니다
- 메인 폭은 줄지 않습니다. 터미널이 좁아지지 않는 것이 밀어내기 대신 이 형태를 고른 이유입니다

## 2. 헤더 — 좁으면 접기

지금은 `[workspace 이름 · 맥락] [🔍 Search ⌘K] [🔔] [⚙] [☀]`입니다.

- 맨 왼쪽에 햄버거(`☰`)를 추가해 드로어를 엽니다. 넓은 폭에서는 보이지 않습니다
- 검색 입력 필드는 돋보기 아이콘 하나로 접고, 누르면 커맨드 팔레트가 열립니다(`⌘K`와 같은 것)
- workspace 맥락(Host의 작업 경로·브랜치, Network의 멤버 수)은 자리가 부족하면 생략하고 이름만
  남깁니다. 이름은 말줄임 처리합니다
- **알림(🔔)·설정(⚙)·테마(☀) 세 아이콘은 헤더에서 빼고 사이드바 드로어로 옮깁니다**(위치는
  11차 2번 참조). 좁은 폭의 헤더에는 햄버거·workspace 이름·검색 아이콘만 남습니다
- 다만 미확인 알림이 있으면 햄버거(`☰`)에 작은 점을 붙여 주세요. 세 아이콘이 드로어 안으로
  들어가면 드로어를 열기 전에는 알림 배지가 보이지 않아 알림이 왔다는 사실을 인지할 경로가
  사라집니다. 정확한 개수는 드로어를 열어 배지로 확인합니다

## 3. 설정 페이지 — 1열로

- 왼쪽 세로 섹션 nav 5개 → 화면 상단 가로 탭 줄로 옮깁니다. 넘치면 가로 스크롤합니다
- 라벨 왼쪽 / 입력 오른쪽 2열 → 라벨 위 / 입력 아래 1열로 쌓고 입력은 폭 전체를 씁니다
- Host layout preset 4개 그림은 한 줄에 안 들어가면 2×2로 접습니다
- 하단의 변경 수 + `Revert` + `Save` 바는 지금처럼 화면 하단에 붙여 둡니다
- **keybindings는 그대로 둡니다.** `Change` 버튼과 키 캡처를 숨기지 마세요. 창을 줄인
  데스크톱에는 물리 키보드가 있습니다. 키 표기 열이 좁으면 행 안에서 줄을 바꾸되 `Change`는
  같은 행에 남깁니다
- dialog 3종(탭 닫기 확인, `Discard changes?`, 저장 시점 충돌)은 좁은 폭에서 가로 여백을 줄이고
  버튼을 세로로 쌓아도 됩니다. 기본 포커스 규칙은 그대로입니다

## 11차 수정 지시 — 헤더 이름 잘림과 드로어 아이콘 위치

9·10차 반영본을 실제로 띄워 폭을 바꿔 가며 확인했습니다. 다국어 철회, 헤더 톱니, 760px
breakpoint, 오버레이 드로어, 햄버거 점, 상단 가로 탭·1열 설정, keybindings의 `Change` 유지,
좁은 폭 가로 스크롤바 없음은 모두 반영됐습니다. 그대로 두세요. 아래 2건만 고쳐 주세요.
1번은 확인된 결함이고, 2번은 10차 지시 자체를 뒤집는 배치 변경입니다.

## 1. 헤더에서 workspace 이름이 먼저 사라집니다

760px 이상, 즉 지금 형태를 유지하는 구간에서 생기는 문제입니다.

사이드바 240px, workspace 이름이 `dev`(3글자)일 때 측정한 값입니다.

| 창 폭 | 이름 폭 | 맥락 폭 |
|---|---|---|
| 895px 이상 | 23px (전부 보임) | 245px |
| 890 → 870px | 21 → 1px | 245px |
| 865 → 760px | **0px (완전히 사라짐)** | 245px |

헤더에는 `· network · 3 agents · 4 terminals`만 남고 정작 `dev`는 보이지 않습니다. 이름이 잘릴
때 말줄임표도 없이 글자가 잘려 나갑니다. 줄어드는 순서가 반대입니다. 맥락은 부차적인 정보이고
이름은 지금 어느 workspace를 보고 있는지를 알려 주는 유일한 표시입니다.

- 폭이 부족하면 **맥락을 먼저 줄이거나 버리고**, 이름은 마지막까지 남깁니다
- 이름이 그래도 넘치면 잘라 내지 말고 말줄임표(`…`)로 처리합니다
- 이 규칙은 760px 경계와 무관하게 모든 폭에 적용합니다. 10차에서 760px 미만에 대해 말한
  "맥락 생략 후 이름 말줄임"과 같은 동작을, 넓은 폭에서도 자리가 부족할 때 그대로 적용하는
  것입니다
- 이름이 짧아서 지금 문제가 늦게 드러난 것뿐입니다. 긴 이름에서는 더 넓은 폭에서 사라집니다

## 2. 세 아이콘을 드로어 상단으로 옮깁니다

10차에서 드로어 **하단**이라고 한 것을 **상단**으로 바꿉니다. 드로어 맨 위 `AIOX` 브랜드 줄
바로 아래에 `[🔔][⚙][☀]` 한 줄을 두고, 그 아래 구분선, 그 아래 WORKSPACES 목록입니다.
드로어 하단은 비웁니다.

바꾸는 이유가 셋입니다.

- 넓은 폭에서 이 세 개는 헤더 오른쪽 **위**에 있습니다. 하단에 두면 창 폭에 따라 같은 컨트롤이
  화면 맨 위와 맨 아래를 오갑니다
- 드로어의 WORKSPACES/NETWORKS/HOSTS 목록은 사용자가 계속 만들어 길이가 정해져 있지 않습니다.
  목록이 화면을 넘기면 하단 고정 아이콘 줄은 스크롤 영역 밖에 따로 고정하거나 목록 위에 떠
  있어야 합니다. 상단은 목록 길이와 무관합니다
- 미확인 점이 붙는 햄버거(`☰`)가 바로 위에 있어 점 → 🔔 → 패널이 한 줄기로 이어집니다

같이 고쳐야 하는 것이 있습니다. 지금 반영본에서 드로어 하단 🔔을 누르면 알림 패널이 드로어에
가려 쓸 수 없습니다. 측정한 값입니다.

- 알림 패널: `left 10px`, `width 340px`, `z-index 60`
- 드로어 backdrop: `z-index 70`
- 드로어: `left 0`, `width 280px`, `z-index 80`

패널이 드로어와 backdrop 아래에 깔려 오른쪽 70px 남짓만 그것도 어둡게 덮인 채로 보이고,
backdrop이 위를 덮고 있어 알림 항목을 누를 수도 없습니다. 세 아이콘을 드로어로 옮기면서
패널만 헤더 기준 위치와 z 순서를 그대로 쓴 결과입니다.

- 아이콘 줄이 상단으로 가면 패널은 그 아래로 펼쳐집니다. 드로어 안에서 아이콘 줄 바로 아래에
  목록을 밀어내며 펼치는 인라인 방식이면 z 순서를 손댈 필요가 없습니다. 이쪽을 권합니다
- 패널을 계속 띄우는 방식으로 두겠다면 드로어보다 위(z 순서 기준)에 올리고 아이콘 줄 아래에
  붙이세요. 이 경우 backdrop 클릭과 `Esc`는 패널 → 드로어 순으로 닫습니다
- 넓은 폭의 알림 패널은 지금 그대로 헤더의 🔔 아래에 둡니다

## 확인용

- 창을 1200px에서 760px까지 천천히 줄이며 헤더의 workspace 이름이 어느 폭에서도 사라지지

## 12차 수정 지시 — 좁은 폭에서 이동한 뒤 드로어가 남습니다

## 1. 알림이나 검색 결과로 이동하면 드로어도 닫습니다

같은 문제가 명령 팔레트(`⌘K`)에도 있습니다. 드로어가 열린 채로 팔레트를 열고 탭 하나를 고르면

- workspace 선택과 설정 진입은 이미 닫고 있습니다. 알림과 팔레트만 빠졌습니다
- 반대로 **이동이 아닌 동작**은 드로어를 열어 둡니다. 테마 토글(☀)이 그렇고 지금 그렇게
  동작합니다. 그대로 두세요

backdrop을 누르면 알림 패널과 드로어가 한 번에 닫히는 것은 그대로 두세요. 11차에서 패널 →
드로어 순으로 닫으라고 했지만 backdrop은 드로어 바깥이고, 거기를 누르는 것은 전부 닫겠다는
뜻으로 보는 편이 낫습니다. `Esc`는 지금처럼 패널 → 드로어 순입니다.

## 13차 수정 지시 — 설정 저장 위치, 알림 읽음 처리, 드로어 닫기 범위

12차 2건은 모두 반영됐습니다. 좁은 폭에서 알림 항목이나 팔레트 결과로 이동하면 드로어가 함께
닫히고, 테마 토글(`☀`)은 드로어를 열어 둡니다. 경계도 `768px`입니다. 그대로 두세요.

이번 4건은 지금까지 지시 사이에 끼어 있던 것들이라 새 기능이 아니라 이미 확정된 정책에 화면을
맞추는 작업입니다.

## 1. `localStorage`를 쓰지 마세요

이 제품의 저장소는 **설정 파일(`~/.aiox/config.json`)과 DB 둘뿐입니다.** 브라우저 저장소에는
아무것도 남기지 않기로 확정했습니다. 포트를 바꾸면 origin이 달라져 브라우저 저장소가 통째로
날아가는데, 그때 설정이 같이 사라지면 안 되기 때문입니다.

지금 `localStorage`에 쓰고 있는 두 값을 설정 파일 모델(`cfgSaved`) 안으로 옮겨 주세요.

- **앱 테마** — 이미 `appearance.theme`가 있습니다. `localStorage`의 `aiox.theme`을 지우고 이
  필드 하나만 진실로 삼아 주세요
- **사이드바 너비** — `web.sidebar.width`로 새로 넣어 주세요. 기본값 `240`, 범위 `180~400`은
  실측으로 확정한 값이라 그대로입니다. `localStorage`의 `aiox.sidebarWidth`는 지웁니다

`web.sidebar.width`는 **설정 화면에 필드로 만들지 마세요.** 사이드바 경계를 끄는 것이 곧 그
값의 편집입니다. 파일 안에 있을 뿐 화면에 입력칸으로 나오지는 않습니다.

## 2. 직접 조작하는 컨트롤은 파일에 바로 씁니다

1번을 하면 곧바로 "그럼 언제 저장되는가"가 문제가 됩니다. 규칙을 이렇게 나눠 주세요.

- **설정 화면의 필드**는 지금 그대로입니다. 바꾸면 변경 카운트에 들어가고 `Save`를 눌러야
  파일에 기록됩니다. 테마는 지금처럼 즉시 미리보기 + `Preview — not saved yet`입니다
- **화면을 직접 조작하는 컨트롤**은 파일에 즉시 씁니다. 헤더와 드로어의 `☀`, 사이드바 경계
  드래그 둘입니다. 편집 중 값과 저장된 값을 함께 갱신하므로 변경 카운트에 남지 않습니다

즉시 쓰기로 하는 이유는 이렇습니다. `Save` 바는 설정 화면에만 있습니다. 워크스페이스 화면에서
`☀`을 눌렀는데 그게 "저장 안 된 변경"이 되면 사용자는 그 변경을 볼 수도 저장할 수도 없습니다.
게다가 그 상태로 설정 화면을 벗어나려 하면 본 적도 없는 변경 때문에 `Discard changes?`가
뜹니다.

지금은 헤더 `☀`이 `appearance.theme`를 건드리지 않고 따로 놉니다. 그래서 `☀`으로 라이트로
바꾼 뒤 설정 화면을 열면 Appearance의 Theme이 여전히 `Dark`를 가리킵니다. 화면은 라이트인데
설정은 다크라고 말하는 상태입니다. 같은 필드를 쓰면 사라집니다.

설정 화면에서 Theme을 미저장 상태로 바꿔 둔 채 `☀`을 누르면, 그 필드는 `☀`이 쓴 값으로
덮이고 변경 카운트에서 빠집니다. 같은 값을 사용자가 직접 다시 고른 것이니 그게 자연스럽습니다.
다른 필드의 미저장 변경은 건드리지 마세요.

`☀`은 지금처럼 dark/light 2단 토글이고 설정 화면의 Theme은 System/Light/Dark 3단입니다.
그건 그대로 두세요.

## 3. 알림 클릭은 읽음 처리이지 목록에서 지우는 것이 아닙니다

알림 항목을 누르면 지금은 그 항목이 목록에서 **사라집니다.** 이건 정책과 다릅니다. 클릭은
**읽음 처리**이고, 알림 기록 자체를 지우는 것이 아닙니다.

표시 규칙은 이미 다 만들어져 있습니다. `read`가 `true`인 항목은 점이 회색이 되고 글씨가
가늘어지고 흐려집니다. 초기 데이터의 세 번째 항목(`Claude · Finished editing…`)이 그렇게
보입니다. 지금은 `read`를 `true`로 만드는 곳이 하나도 없어서 그 표시가 쓰이지 않을 뿐입니다.

- **항목 클릭** — `read`를 `true`로 바꾸고 해당 pane으로 이동합니다. 항목은 목록에 남아 흐리게
  보이고 미확인 수만 줄어듭니다
- **`Mark all read`** — 목록을 비우지 말고 전부 `read: true`로 바꿉니다. 이름 그대로입니다
- **항목의 `×`** — 이것만 목록에서 치웁니다. 사용자가 명시적으로 지운 것이므로 그대로 두세요

## 1. Host layout preset을 `3 + 1`로 접지 마세요

10차 3번은 "Host layout preset 4개 그림은 한 줄에 안 들어가면 2×2로 접습니다"였습니다. 지금은
카드 폭이 고정된 채 들어가는 만큼 채우는 방식이라, 한 줄에 셋만 들어가는 폭에서 `3 + 1`이 됩니다.

실측입니다.

```text
360px       [auto][left]            2 x 2    지시대로
            [top ][grid]

400px       [auto][left][top]       3 + 1    ← 고칠 것
            [grid]

500~767px   [auto][left][top][grid] 4 x 1    한 줄에 들어감. 접을 이유 없음

768px       [auto][left]            2 x 2    지시대로
            [top ][grid]

900px       [auto][left][top]       3 + 1    ← 고칠 것
            [grid]
```

`3 + 1`은 마지막 한 장만 줄에서 떨어져 나와 네 개가 같은 묶음으로 보이지 않습니다. 네 preset은
같은 층위의 선택지라 한 줄에 넷이거나 2열씩 두 줄이어야 합니다.

- 한 줄에 **네 개가 들어가면** 그대로 `4 x 1`입니다
- **안 들어가면** 곧바로 `2 x 2`입니다. 3열은 쓰지 마세요

폭이 아니라 카드 개수로 갈리는 규칙이므로 breakpoint를 새로 만들지 마세요. `768px` 하나 그대로이고,
좁은 폭·넓은 폭 어디서나 같은 규칙입니다. 넓은 폭에서도 사이드바가 공간을 먹어 `3 + 1`이 나오므로
이건 좁은 폭 전용 수정이 아닙니다.

## 2. 헤더의 `hasMeta`를 지워 주세요

헤더 컴포넌트에 넘기는 값 중 `hasMeta`가 있습니다. `!!headMeta && !s.narrow`로 계산되는데
마크업 어디에서도 쓰지 않습니다. workspace 이름과 맥락은 각각 `wsName`·`wsMeta`를 직접 씁니다.

계산식의 `!s.narrow`는 "좁은 폭이면 맥락을 통째로 숨긴다"는 11차 이전 방식입니다. 11차·12차에서
맥락을 폭 기반 말줄임 하나로 통일하면서 이 게이트가 필요 없어졌는데 계산만 남았습니다.

- `hasMeta`를 계산하는 줄과 컴포넌트로 넘기는 자리를 함께 지워 주세요
- 마크업은 건드리지 마세요. 지금 아무것도 참조하지 않으므로 화면은 바뀌지 않아야 합니다
- 이걸 "되살려서 쓰는" 방향은 아닙니다. 좁은 폭에서 맥락을 숨기는 동작을 다시 넣지 마세요

## 그대로 둘 것 — 헤더 이름과 맥락의 폭 규칙

1번과 2번 모두 헤더와 설정 화면을 건드리므로, 딸려 바뀌기 쉬운 것을 먼저 못박습니다.

workspace 이름과 맥락은 **폭 기반 단일 규칙 하나**입니다. 맥락이 먼저 줄고 이름이 마지막까지
남으며, 넘치면 말줄임표를 씁니다. 이 규칙은 `768px` 경계와 무관하게 모든 폭에 적용합니다.

창을 `767px`에서 `768px`로 넓히면 맥락이 오히려 더 짧아집니다. 좁은 폭에서는 드로어가 떠 있는
오버레이라 헤더가 화면 전폭을 쓰고, `768px`부터는 사이드바가 자리를 차지하기 때문입니다. **이건
의도한 결과입니다.** 드로어가 메인 폭을 줄이지 않기로 한 것과 같은 규칙이므로 고치지 마세요.
경계 전용 예외를 넣거나, 이름을 줄여 맥락을 살리거나, 맥락에 최소 폭을 주는 식의 보정을 하지
마세요.

## 확인용

- 창을 `360px`부터 `1280px`까지 천천히 넓히면서 Host layout preset을 봅니다. 어느 폭에서도
  `3 + 1`이 나오면 안 됩니다. `4 x 1`과 `2 x 2` 둘만 나와야 합니다
- 같은 구간에서 가로 스크롤바가 생기지 않는지 함께 봅니다
- 헤더에서 workspace 이름이 어느 폭에서도 사라지지 않고, 맥락이 먼저 줄어드는지 봅니다
- `767px` → `768px`로 넘길 때 맥락이 짧아지는 것은 그대로여야 합니다

# AIOX 운영 Web UI 디자인 프롬프트 (Stage 6, 3차: Host Agent 종료와 재시작)

실행 계약은 `docs/specs/aiox-host.md`, 화면 계약은 `docs/specs/aiox-configuration-web.md`를
따릅니다. 이 프롬프트의 목업 구현·검토 제안은 실제 daemon 구현 완료를 뜻하지 않습니다.

## 이 화면이 무엇인가

`HOSTS`의 panel은 YAML 파일 하나에 선언된 Agent 묶음의 작업 화면입니다. Agent마다 shell을
하나 만들고 **그 shell 안에서** CLI를 실행해 vendor TUI를 띄웁니다. 그래서 Agent 탭은 처음부터
끝까지 shell 위에 있습니다.

지금 목업에는 실행 중인 Agent 탭만 있습니다. Agent가 끝나고, 안내가 뜨고, 다시 시작해서 같은
자리로 돌아오는 과정이 통째로 없습니다. 이번에 그 수명을 만듭니다.

새 화면이나 새 페이지를 만드는 것이 아닙니다. 지금의 panel·pane·탭 구조와 스타일 안에서 **탭
본문과 탭 라벨이 바뀌는 것**입니다. UI 문구는 영어입니다.

## 큰 규칙 — 멈추는 방식이 두 가지이고 화면이 다릅니다

```text
Agent TUI 실행 중
├─ 사용자가 TUI 안에서 /exit    → 그 탭은 일반 shell로 돌아갑니다
└─ AIOX에 명시적으로 stop 요청  → 그 탭에 stopped 안내가 뜹니다
```

프로그램을 끝내면 prompt로 돌아오는 것이 shell의 원래 흐름이라 `/exit`은 shell을 보여줍니다.
반대로 AIOX가 멈춘 것은 사용자가 그 자리에서 기대하던 흐름이 아니므로 무엇이 멈췄고 어떻게 다시
시작하는지 안내가 필요합니다.

둘 다 **실제로 프로세스가 끝난 뒤**의 이야기입니다. 오류 메시지가 떴거나 사용량 제한에 걸렸거나
화면 연결이 끊긴 것만으로는 종료가 아닙니다. 그런 경우는 지금처럼 `failed`·화면 연결 경고 표시를
유지하고 이 안내로 바꾸지 마세요.

## 1. stopped 안내

Agent 탭 본문을 TUI 대신 이 안내로 바꿔 주세요. 탭 라벨에는 `· stopped`를 붙입니다.

```text
┌─ [planner · stopped  ×] ────────────────────┐
│                                             │
│   Agent has stopped.                        │
│                                             │
│   aiox host agent start planner             │
│                                    [Copy]   │
│                                             │
└─────────────────────────────────────────────┘
```

세 가지 경우가 있고 첫 줄과 이유만 다릅니다. 명령과 `Copy`는 셋 다 같습니다.

| 경우 | 첫 줄 | 이유 |
|---|---|---|
| AIOX stop으로 멈춤 | `Agent has stopped.` | 없음 |
| 비정상 종료 | `Agent exited unexpectedly.` | 종료 이유를 그대로 |
| 시작 실패 | `Agent failed to start.` | 실패 이유를 그대로 |

이유는 지금 `planner` 탭이 `failed`일 때 쓰는 것과 같은 자리·같은 서식으로 보여 주세요.

**명령 문자열은 고정 문자열이 아닙니다.** 그 Agent를 실제로 시작할 수 있는 명령이어야 하므로 대상
YAML을 고르는 데 필요하면 `--path`나 `--file`이 붙습니다. 목업에서는 Host마다 "어느 파일에서
왔는지"를 데이터로 들고 있다가 명령을 만들어 주세요.

- 기본값(`aiox.yaml`, 현재 디렉터리)이면 `aiox host agent start planner`
- 다른 파일이면 `aiox host agent start planner --file aiox.dev.yaml`

아래 확인용 디버그 패널에서 두 형태를 다 볼 수 있어야 합니다.

`Copy`를 누르면 **명령을 클립보드에 복사하고, 같은 탭을 일반 shell로 바꿉니다.** 새 탭이나 새
pane을 만들지 않고 명령을 자동으로 실행하지도 않습니다. 복사됐다는 짧은 피드백(`Copied`)을 주세요.
복사한 명령은 실행 시의 YAML 선택 규칙대로 실행합니다. YAML의 Host 이름이 바뀌었다면
그 현재 이름의 Host가 대상이며, 원래 탭의 Host와 다르다는 이유로 거절하지 마세요.
원래 Host로 대상을 강제하지 않으며 다른 Host panel에서의 실행 배치 규칙을 그대로 적용합니다.
stop에서도 기반 shell은 살아 있습니다. Copy는 그 기존 shell을 다시 표시하며 새 프로세스를 만들지 않습니다.
사용자가 거기에 명령을 붙여 넣어 실행하면 같은
자리에서 TUI가 뜹니다.

## 2. `/exit`은 shell로 돌아옵니다

Agent 탭에서 사용자가 TUI를 정상적으로 끝내면 그 탭은 **stopped 안내를 거치지 않고 바로 일반
shell**이 됩니다. 탭 이름도 shell 이름으로 바뀝니다. 그 shell은 Agent가 시작되기 전에 있던 바로
그 자리입니다.

이때도 Host가 관리하는 Agent 항목 자체는 멈춘 상태입니다(7번 참고). 탭에 shell이 보이는 것과 그
Agent가 지금 돌고 있는 것은 다릅니다.

## 3. 재시작은 같은 탭에서 이어집니다

stopped 안내가 떠 있는 탭에서 그 Agent가 다시 시작되면, 새 탭을 만들지 말고 **같은 탭에서**
이어 주세요.

```text
stopped 안내 → 준비 중 → TUI
```

준비 중에는 이미 있는 `aiox-preparing` 상태를 씁니다. 지금 이 값은 색만 정의돼 있고 어디에도
쓰이지 않습니다. 탭 라벨은 `planner · preparing`이고 본문은 준비 중이라는 것과 무엇을 기다리는지
한 줄이면 됩니다. 준비가 끝나면 TUI로 바뀝니다.

시작에 실패했다면 준비 완료로 넘어가지 말고 1번 표의 `Agent failed to start.`로 갑니다.

## 4. 같은 Agent를 다른 shell에서 시작하면 자리가 옮겨집니다

사용자가 같은 Host panel의 **다른 shell**에서 그 Agent를 시작할 수 있습니다. 그러면 TUI는 명령을
입력한 그 shell 자리에 뜹니다.

여기도 3번과 같은 start이므로 그 Agent는 `aiox-preparing`을 거칩니다. 다만 **본문에 보이는 것이
다릅니다.** 3번은 안내 화면을 준비 중 안내로 바꾸지만, 여기는 사용자가 방금 명령을 친 **살아 있는
shell**입니다. 본문은 그 shell 그대로 두고 명령 출력이 흐르게 하세요. 살아 있는 shell을 준비 중
안내로 덮지 마세요. 준비 중이라는 것은 탭 라벨(`planner · preparing`)과 Host 카드 칩으로 보입니다.
준비가 끝나면 같은 자리에서 TUI로 바뀝니다.

- 옛 탭이 아직 **stopped 안내**라면 그 탭을 제거합니다. 같은 Agent의 안내가 두 군데 남지 않게
  하는 것입니다. **다만 준비가 끝나 새 TUI가 연결된 뒤에 제거하세요.** 준비 중에는 두 자리가 잠깐
  함께 있습니다. 시작될 것이라고 미리 지우면 시작이 실패했을 때 사용자가 다시 시작할 자리를 잃습니다
- 새 자리에서 **시작에 실패하면** 그 자리에 `Agent failed to start.`와 이유를 표시하고,
  **옛 stopped 탭은 그대로 둡니다.** 실패 안내를 통합하려고 옛 탭을 삭제하지 마세요.
- 옛 탭이 이미 `Copy`를 눌러 **일반 shell**이 됐다면 그대로 둡니다. 그건 이제 사용자의 터미널이고
  거기서 다른 일을 하고 있을 수 있습니다
- 사용자가 쓰던 아무 shell이나 골라서 TUI로 덮어쓰지 마세요. 명령을 실제로 입력한 자리만 씁니다

## 5. 같은 panel의 shell에서 여러 Agent를 한 번에 시작하면

`aiox host agent start planner tester`처럼 둘 이상을 함께 시작할 수 있습니다.

- **첫 번째** Agent는 명령을 입력한 shell 자리에 뜹니다
- **나머지**는 그 panel의 다음 순서에 새 탭으로 뜹니다

순서는 지금 쓰는 배치 순서(화면의 위→아래, 왼쪽→오른쪽)와 같습니다. 기존 탭의 자리는 건드리지
않습니다.

## 6. stopped 탭의 `×`는 바로 닫습니다

지금은 Agent 탭의 `×`가 **항상** 확인 창을 띄웁니다. 살아 있는 agent는 AIOX가 한가한지 알 수
없다는 이유였고 그건 그대로 맞습니다. 하지만 stopped 안내가 떠 있는 탭에는 **실행 중인 Agent가 없습니다.** 기반 shell은 살아 있으므로
확인 없이 해당 shell을 정리하고 탭을 닫아 주세요.

- 실행 중인 Agent 탭 → 지금처럼 확인 창
- stopped 안내 탭 → 확인 없이 닫힘
- 탭을 닫아도 YAML에 적힌 Agent 정의는 사라지지 않습니다. 7번처럼 Host 카드에는 남습니다
- 마지막 탭을 닫아도 지금처럼 panel과 빈 pane과 `[+]`를 유지합니다. shell을 자동으로 만들지
  않습니다

## 7. Host 카드의 agent 목록은 탭이 아니라 선언을 따릅니다

지금 섹션 카드의 agent 목록은 **열려 있는 탭에서 뽑아** 만듭니다. 그래서 탭을 닫으면 그 Agent가
카드에서도 사라집니다. Host에서는 이게 틀립니다. YAML에 선언된 Agent는 탭이 없어도 그 Host의
구성원입니다.

Host panel마다 **실제로 적용된 Agent 이름 목록**을 데이터로 따로 들고, 카드는 그 목록을 그려 주세요.
파일만 편집하고 아직 start/restart로 적용하지 않은 정의를 현재 구성으로 표시하지 마세요.
탭이 있으면 그 탭의 상태를, 탭이 없거나 멈춰 있으면 멈춘 표시를 보여 줍니다.

멈춘 Agent는 상태 다섯 값(`aiox-preparing`·`idle`·`working`·`awaiting-user`·`failed`)에 **새
값을 추가하지 말고** 이렇게 구분해 주세요. 그 다섯은 살아 있는 프로세스가 지금 무엇을 하는지를
말하는 값이고, 멈춤은 프로세스가 없다는 뜻이라 층이 다릅니다.

- 상태 점을 채우지 말고 **테두리만 있는 회색 점**으로 그립니다
- 칩 전체를 흐리게 합니다. 읽은 알림 항목과 같은 어휘입니다

`NETWORKS`·`WORKSPACES` 카드는 지금 그대로 둡니다.

## 8. Host를 restart하면 탭이 늘거나 줄어듭니다

YAML을 고치고 Host 전체를 restart하면 Agent 구성이 바뀔 수 있습니다.

| YAML 변화 | 화면 |
|---|---|
| 같은 이름이 그대로 | 그 탭이 남아 있으면 **자리를 유지한 채** 다시 실행 |
| Agent 추가 | 다음 순서에 새 탭 |
| Agent 삭제 | 그 Agent의 탭을 종료하고 제거 |
| 이름 변경 | 옛 이름을 삭제하고 새 이름을 추가한 것으로 봅니다 |
| 그 Agent의 탭이 이미 닫혀 있음 | 다음 순서에 새 탭 |

**사용자가 만들어 둔 pane 배치를 다시 정렬하지 마세요.** 탭만 늘고 주는 것입니다.

지우지 않는 것도 분명히 해 주세요. 사용자가 직접 추가한 shell과 `/exit` 또는 `Copy` 뒤 일반 shell이 된 탭은
restart로 사라지지 않습니다. 삭제된 Agent가 실행 중인 shell 또는 stopped 안내 뒤 shell은
실제 프로세스 종료를 확인한 뒤 탭과 함께 제거합니다.

Host 이름이 바뀌면 기존 panel을 rename하거나 지우지 않고 별도 Host panel과 Network로 실행합니다.
YAML을 읽지 못하거나 사전 검증에 실패하면 기존 실행·화면을 그대로 유지하며 CLI에 안내합니다.
같은 YAML·같은 Host 이름으로 run을 반복해도 새 panel을 만들지 않고 CLI로 기존 상태와
start/restart 방법을 안내합니다. 파일 선택은 디렉터리 `--path`와 파일 `--file`로 나눕니다.
`--file` 생략 시 후보 `aiox.yaml`/`aiox.*.yaml`이 복수이면 안내만 하고 실행하지 않습니다.

## 9. `stop`과 `delete`의 확인 창을 나눠 주세요

지금은 `Delete "<name>"?` 하나뿐인데 둘은 없애는 것이 다릅니다.

```text
Stop "development"?
Stops the agents declared in this host. Your shells, this panel and its
network stay. You can start the agents again later.
                                          [Cancel]  [Stop agents]

Delete "development"?
Ends every terminal in this panel, including shells you added and the work
inside them, then removes the panel and its network. The YAML file stays.
                                          [Cancel]  [Stop and delete]
```

`Delete` 쪽 문구는 지금 것을 이 내용으로 바꿔 주세요. 지금은 "터미널을 멈춘다"까지만 말하고 사용자
shell과 network까지 없어진다는 것을 말하지 않습니다.

## 넣지 말 것

- 종료 안내에 종료 직전 TUI 출력을 남기지 마세요. 안내가 본문을 대체합니다
- `Restart` 버튼을 만들지 마세요. 재시작은 명령으로 합니다. 안내에 있는 것은 복사할 명령뿐입니다
- stopped 상태를 agent 상태 다섯 값에 추가하지 마세요
- YAML을 읽거나 고치는 화면을 만들지 마세요. 이번 범위가 아닙니다
- worktree 관련 화면을 만들지 마세요. 이번 범위가 아닙니다

## 확인용 — 디버그 패널에 추가해 주세요

지금 디버그 패널에 있는 것들과 같은 자리에 넣어 주세요. daemon도 agent도 없는 목업이라 이 상태들을
눈으로 보려면 토글이 필요합니다.

- **Stop agent** — 고른 Agent를 명시 stop으로 멈춥니다. 1번의 첫 줄 `Agent has stopped.`
- **Exit agent** — 고른 Agent가 `/exit`으로 끝납니다. 2번의 shell 복귀
- **Crash agent** — 비정상 종료. `Agent exited unexpectedly.` + 이유
- **Fail to start** — 시작 실패. `Agent failed to start.` + 이유
- **Start agent** — stopped 탭을 준비 중으로 바꾸고 잠시 뒤 TUI로 잇습니다. 3번
- **Start from another shell** — 같은 Host의 다른 shell 자리에서 시작합니다. 4번.
  준비 중에 멈춰 두 자리를 함께 볼 수 있게 하고, 성공과 실패를 둘 다 낼 수 있게 해 주세요
- **Start two agents** — 5번의 첫 번째·나머지 배치
- **Host YAML file** — `aiox.yaml`과 `aiox.dev.yaml` 중에 고릅니다. 1번의 명령 문자열이
  `--file`을 달고 바뀌는지 봅니다
- **Restart host: add / remove / rename agent** — 8번의 세 경우

확인은 이렇게 합니다.

- 명시 stop한 탭에 안내가 뜨고, `Copy`를 누르면 같은 탭이 일반 shell이 되며 새 탭이 생기지 않는지
- `/exit`한 탭은 안내 없이 바로 shell이 되는지
- stopped 탭의 `×`가 확인 창 없이 닫히고, 실행 중인 탭의 `×`는 여전히 확인 창을 띄우는지
- 탭을 닫은 Agent가 Host 카드에는 테두리 점으로 남아 있는지
- 다른 shell에서 다시 시작했을 때 준비 중에는 두 자리가 함께 있다가 TUI가 뜬 뒤에 옛 stopped 탭이
  사라지는지, `Copy` 뒤 shell이 된 탭은 남는지
- 새 자리에서 시작이 실패했을 때 그 자리에 실패 안내가 뜨고 옛 stopped 탭은 그대로 남는지
- restart로 Agent를 지웠다 더해도 사용자가 만든 pane 배치가 그대로인지
- Host YAML 파일을 바꿨을 때 안내의 명령에 `--file`이 붙는지
