## 2026-06-10 · log skill 심볼릭 링크 통합

@user

- Claude·Codex log skill 본문이 거의 같으니 심볼릭 링크로 단일 파일 통합을 검토하자.
- 환경은 mac 단독. 크로스플랫폼·Windows 심링크 우려는 배제한다.
- 통합 방식은 Codex 쪽과 토론해 정한다.

@claude

- 정합 대조: 두 SKILL.md는 규칙 충돌 없이 의미상 정합하다. 차이는 배치·예시 표현
  수준이고, 유일한 실질 차이는 frontmatter `description` 하나다. Claude는 트리거
  예시(`예 "로그 남겨줘"…`)를 포함하고 Codex는 포함하지 않는다.
- 성능 영향: skill은 progressive disclosure라 평소에는 `name`+`description`만 떠
  있고 발동 후 본문 전체가 로드된다.
  - `description`(트리거 예시): 본문 로드 전 발동 여부를 판단하는 유일한 근거라
    자동 발동 정확도에 실질 영향을 준다. `/log` 명시 호출만 하면 영향이 작다.
  - 본문 섹션 순서: 발동 후 본문 전체가 컨텍스트에 들어와 규칙 충돌만 없으면 동작
    차이가 거의 없다.
  - 예시 코드블록: 형식 준수 정확도에 약한 양의 영향, 토큰 비용은 약간 증가한다.
- 심링크 통합 트레이드오프: 심링크는 두 경로를 완전히 같은 한 파일로 만들어
  frontmatter `description`도 강제로 같아진다. SKILL.md는 frontmatter+본문이 한
  파일이라 "본문만 공유"가 불가능하다.
  - 따라서 완전 통합 가능 여부는 "Claude·Codex가 같은 `description` 하나로 둘 다 잘
    발동하는가"로 갈린다. 가능하면 심링크가 정답이고, 불가능하면(`description`이
    하네스별로 달라야 하면) 본문 복사 같은 다른 동기화가 필요하다.
- 미확인: Codex·Claude 하네스가 심링크된 SKILL.md를 정상 로드하는지는 실측이
  필요하다. 특히 Codex 쪽.

미결 (Codex 토론에서 확정)

- Codex의 `description`이 짧은 것이 의도인지 미확정.
- 통합 방향(어느 쪽을 실제 파일, 어느 쪽을 링크)도 미확정.

- [x] Codex와 aiox로 (a) `description` 단일화 발동, (b) Codex 심링크 로드,
  (c) 통합 방향을 토론·확정했다. (아래 `통합 합의와 검증 완료` 블록)

  위험이 있다(사용자 확인).
- 정본 파일 확인: `.agents/skills/log/SKILL.md`(inode 24186674)에 Claude 편집이
  그대로 있다 — line 3 통일 `description`, line 99 무효 체크박스 코드블록 예시 모두
  반영, 옛 버전 흔적 0건. inode가 통합 내내 동일해 Codex가 `mv`로 정본을 이동했고
  편집이 보존됐음을 확인. Codex가 자기 버전으로 덮은 것이 아니다.
- Skill 발동: `/log` 호출 시 Base directory가 `.claude/skills/log`로 나와 Claude가
  심링크 경로로 skill을 발동함은 확인. 단 호출 본문이 시작 시점 캐시라 옛 본문으로

  일치한다.
- 결론: 정본 파일·파일시스템 통합·심링크 경로 발동은 확인. 남은 것은 세션 캐시
