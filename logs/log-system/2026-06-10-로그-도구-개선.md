문제 정의

@claude · @codex

- `$log 점검`은 별도 skill이나 엄격한 CLI 명령 체계가 아니라 기존 log skill이
  인식하는 대표적인 자연어 점검 요청으로 둔다.
- 대상 로그는 기존 재개 규칙대로 사용자 요청, plan 현재 단계 또는 부모 로그의 분리
  포인터로 하나가 특정되면 그 로그를 사용한다. 특정되지 않으면 관련 open 로그
  후보를 보여주고 사용자가 선택하게 하며, 사용자가 전체 open 로그를 지정한 경우에만
  모두 점검한다.
- `scripts/log audit <파일>...`은 fenced code 밖 실제 미완료 체크박스의 파일, 행 번호와
  소속 `##` 블록만 출력한다. 죽은 항목, 완료, 취소, 분리 여부를 판정하거나 본문을
  수정하지 않는다.
- agent는 audit 결과를 후속 기록과 대조해 `완료가 명백함`, `계속 유효함`, `판단 필요`로
  분류하고 사용자에게 보고한다. 점검 단계에서는 `[x]`, 취소, 분리나 이관을 적용하지
  않는다.
- `$log 정리`라는 별도 동작은 만들지 않는다. 실제 수정은 점검 보고를 본 사용자의
  구체적 지시와 기존 완료·취소·분리 규칙에 따라 수행한다.
- `scripts/log set-status`는 같은 구조 검사 로직을 사용해 `decided`나 `superseded` 전환
  시 실제 미완료 체크박스가 있으면 위치를 출력하고 전환을 거부한다. `open` 전환은
  허용한다.
- hook은 audit과 다른 판단을 하지 않는 자동 호출 계층으로 유지한다. 수동 점검과
  guard를 먼저 검증한 뒤, 수정된 로그나 세션 종료 시 같은 사실 목록을 비차단으로
  노출하도록 설계한다. Claude `SessionEnd`와 Codex의 turn 단위 `Stop`·`PostToolUse`가
  비대칭이므로 양쪽 hook 입력, 출력 주입, 중복 경고와 비차단 동작을 별도로 검증한다.
- hook 후보와 재개 상태는 이 `로그 도구 개선` 로그만 소유한다. 수동 점검과 guard
  검증 전에는 log skill이나 script에 미래 hook 이름, 절차 또는 빈 설정을 남기지 않는다.
- log skill에는 블록 제목의 상대어 지양, 수행한 직전 `다음:` 닫기, 재개 중 후속
  기록으로 완료가 명백한 항목만 닫고 불명확하면 보고하는 규칙을 최소 보완한다.
  같은 로그 안의 판단어는 superseded 전용인 `이관` 대신 `분리`를 사용한다.

## 2026-06-11 · 예방 규칙과 구조 대안 비교

검토한 log skill 보완 문구

1. 블록 제목의 상대어 지양
   - 블록 제목의 `<주제>`는 시간이 지나도 의미가 변하지 않는 이름으로 쓴다.
     `다음`·`현재`·`최종`처럼 작성 시점에 상대적인 표현은 피한다. 본문 끝의
     `- [ ] 다음:`은 재개 행동을 표시하는 별도 형식이므로 이 제한에 해당하지 않는다.
2. 수행한 직전 `다음:` 닫기
   - 새 블록을 이어 쓸 때 직전 `- [ ] 다음:`이 가리킨 행동을 수행했다면 새 블록을
     쓰기 전에 해당 항목을 `[x]`로 닫는다. 결정 변경으로 무효가 됐다면 기존 취소
     규칙을 따르고, 분리 로그를 처리한 경우에는 기존 분리 절차에 따라 닫는다.
   - 이 규칙은 직전 행동만 대상으로 하며 새 블록마다 본문 전체를 판정하게 하지 않는다.
3. 재개 중 명백한 누락 보정
   - 다른 미완료 항목을 확인하다 이미 수행된 사실이 후속 기록으로 명백히 확인되면
     `[x]`로 닫는다. 완료·취소·분리 여부가 불명확하면 독단으로 변경하지 않고
     사용자에게 보고한다.
   - 전체 로그 스캔이나 취소·분리의 자동 의미 판정을 의무화하지 않는다.

### `scripts/log audit`

- 기존 `scripts/log`에 `audit` 서브커맨드를 추가한다. 별도 `scripts/log-audit` 파일은
  만들지 않는다. 수동 `$log 점검`과 status guard가 같은 구조 검사를 사용하므로
  `scripts/log` 안의 공용 검사 함수가 두 소비자에게 결과를 제공한다.
- 예상 호출은 `scripts/log audit <파일> [파일...]`이다. script는 대상 로그를
  선택하지 않고 전달받은 파일만 검사한다. 대상 선택은 사용자 요청과 skill의 책임이다.
- 공용 구조 검사는 fenced code를 추적해 그 안의 예시 체크박스를 제외한다. 실제
  Markdown 본문에 있는 미완료 `- [ ]`마다 파일 경로, 행 번호와 가장 가까운 위쪽
  `##` 블록 제목을 출력한다.
- audit은 구조적 사실만 출력한다. 항목이 흩어졌는지, 죽었는지, 완료·취소·분리·이관
  대상인지를 판정하지 않고 로그 본문을 수정하지 않는다. 정보성 점검이므로 open
  로그에 미완료가 있어도 그 사실만 출력한다.
- agent는 audit 목록을 후속 기록과 대조해 `완료가 명백함`, `계속 유효함`, `판단 필요`로
  분류한다. 이 분류와 근거를 사용자에게 보고하되 점검 중에는 본문을 변경하지 않는다.

### `set-status` guard

- `scripts/log set-status <파일> decided|superseded`는 audit과 같은 공용 구조 검사
  함수를 호출한다. fenced code 밖 실제 미완료 체크박스가 하나라도 있으면 파일·행·
  블록 위치를 출력하고 상태 변경을 거부하며 실패 상태로 종료한다.
- guard는 `decided`·`superseded` 로그에는 남은 미완료가 없어야 한다는 기존 lifecycle
  불변식만 강제한다. 각 항목의 의미나 처리 방법은 판정하지 않고 본문을 수정하지 않는다.
- `open`으로 상태를 바꾸는 동작은 항상 허용한다. open 로그의 여러 미완료는 정상일
  수 있으므로 일반 편집이나 audit에서 차단하지 않는다.

### 실제 사용 흐름

### Hook 계층

- hook은 사용자의 `$log 점검` 호출과 별개로 lifecycle 이벤트에서 같은 audit을 자동
  호출하는 계층이다. audit과 다른 의미 판정이나 자동 수정을 하지 않고 구조적 사실을
  비차단 방식으로 노출하는 역할만 후보로 둔다.
- 첫 구현에는 hook을 섞지 않는다. skill, audit, guard를 기존 로그에 적용해 출력
  정확도, 오탐, 사용성과 실행 빈도를 확인한 뒤 상세 glue를 결정한다. 그 전에는
  skill·script에 미래 hook 이름, 절차나 빈 설정을 남기지 않는다.
- Claude는 실제 세션 종료 시 `SessionEnd`를 지원하며 `PostToolUse`도 후보가 된다.

  `PostToolUse` 또는 제한된 `Stop` 사용을 별도로 검토한다.
- 구현 전 양쪽에서 hook 입력의 수정 파일 경로 형식, stdout/stderr 또는 context 주입
  방식, 편집과 turn을 막지 않는 비차단 동작, 한 turn의 다중 편집과 중복 경고 억제,
