# 기록 계약

이 문서는 로그를 만들거나 본문을 기록할 때 읽는다.

## 목차

- Frontmatter
- 기록할 내용
- 생략할 내용
- 날짜 블록 형식
- Work Items와 Resume Pointer
- 외부 출처

## Frontmatter

frontmatter는 다음 세 필드만 사용한다.

- `topic`: 로그의 짧은 제목
- `description`: 본문을 열지 않고 필요한 로그인지 판별하는 안정적인 index 설명
- `status`: 로그의 수명인 `open`, `decided`, `superseded`

`description`에는 현재 단계나 Resume을 넣지 않는다. 현재 진행 상태와 handoff는
본문의 최신 기록, Work Items와 Resume Pointer가 소유한다. `status`는 log 도구의
`set-status`로만 바꾼다. log 도구는 description과 본문의 의미를 작성하지 않는다.

## 기록할 내용

본문은 다음 agent가 작업을 이어가는 데 필요한 의미를 날짜별로 증류한다.

- 사용자의 의도, 질문, 제약, 피드백, 승인과 거부
- agent의 제안, 선택지, 판단과 근거
- 반대 근거, 동의되지 않은 의견과 보류 이유
- 결정과 결정이 변경된 이유
- 수행한 작업과 검증 결과
- 남은 질문, Work Items와 Resume Pointer
- 판단·결정 또는 후속 확인에 사용한 외부 출처
- 외부 자료에서 확인한 사실과 그 사실이 판단에 미친 영향

기존 로그에 이미 있는 내용을 다시 언급했을 뿐 의도, 판단, 제약, 현재 상태 또는
Resume Pointer가 달라지지 않았다면 추가하지 않는다. 수행·검증 결과와 사용자
승인·거부는 의미 변화로 본다.

기록 여부는 다음 질문으로 판단한다.

> 이 내용을 빼면 다음 agent가 의도, 판단, 근거, 제약, 현재 상태 또는 남은 일을 잘못
> 이해할 가능성이 있는가?

애매하면 결정, 근거, 제약과 미결 사항은 남긴다.

## 생략할 내용

- 반복 질문과 같은 의미의 답변
- 단순 확인이나 진행 발언
- 사용자 이해만을 위한 설명과 예시
- 판단에 영향을 주지 않은 검색 과정과 실패한 검색어
- 외부 자료의 긴 원문
- 이미 기록된 배경의 반복
- 대화 전체의 원문 덤프

설명이나 예시를 통해 조건이 새로 확정됐다면 예시는 버리고 확정된 조건만 기록한다.
세션 종료 때 대화를 일괄 복사하지 않는다. 결정·제약 확정, 판단에 영향을 주는 조사,
작업·검증 완료, 주제 전환과 중단 시점을 기록 checkpoint로 삼는다.

## 날짜 블록 형식

- `## YYYY-MM-DD · <주제>` heading을 사용하고 블록을 시간순으로 이어 쓴다.
- 주제는 `다음`, `현재`, `최종` 같은 상대 표현 대신 시간이 지나도 의미가 유지되는
  이름으로 쓴다.
- 한 블록에는 서로 관련된 질문, 조사나 작업 한 묶음만 둔다.
- 기본 골격은 `@user`와 실제 agent 화자 아래에 의미를 증류한 bullet을 두는 형식이다.
- 사용자의 질문, 답변, 피드백, 승인과 거부는 `@user`로 기록한다.
- agent는 `@codex`, `@claude`, `@gemini`처럼 실제 화자를 쓴다. `@agent`나
  `@user-answer` 같은 공통·별도 표시는 만들지 않는다.
- 승인과 거부는 `승인:`, `거부:`처럼 행위와 범위를 분명히 쓴다.
- 사실, 관찰과 판단은 일반 bullet로 쓰고 수행할 행동에만 체크박스를 사용한다.
- 토론 없이 수행한 작업과 검증만 기록하면 화자 없이 체크리스트와 결과를 둘 수 있다.
- 결론이 없어도 이후 판단과 남은 작업에 영향을 주는 조사, 제안, 관찰과 보류 질문은
  남긴다.
- 모든 블록에 같은 섹션이나 `conclusion`을 강제하지 않는다.

## Work Items와 Resume Pointer

`Work Items`는 로그 수명 안에서 수행할 전체 범위다. 0개 이상 둘 수 있고 단일·복수,
순차·비순차 작업을 표현한다. 순서가 의미 있으면 번호 체크리스트를 사용한다.

```markdown
## Work Items

1. [ ] Inspect API responses.
2. [ ] Test error handling.
3. [ ] Document retry behavior.
```

`Resume Pointer`는 Work Items 전체가 아니라 중단 후 다시 시작할 단일 진입점이다.
open 로그는 fenced code 밖의 미완료 Resume을 최대 하나만 가진다.

```markdown
- [ ] Resume: Start with work item 1.
```

Resume은 본문에 직접 쓰지 않고 append의 `--resume`으로 생성한다. 기존 Resume이 없으면
mode 없는 `--resume`으로 최초 포인터를 만들 수 있다. 진행 기록만 추가하고 기존
진입점이 계속 정확하면 mode 없이 append해 원래 위치의 Resume을 유지한다.

Resume 행동을 수행했다면 `--complete-resume`으로 원래 항목을 `[x]`로 닫는다. 이어갈
행동이 있으면 같은 append의 `--resume`으로 새 블록 끝에 둔다.

완료·취소·대체는 원래 항목 자체를 구조적으로 갱신한다(`[x]` 또는
`Cancelled Resume:` 기록으로 변환). 후속 블록의 서술만으로 원래 체크박스가
해소됐다고 보지 않는다. audit 등 구조 소비자는 후속 서술을 의미적으로 결합하지 않기
때문이다. 미완료 Resume이 여러 개면 자동으로 하나를 고르거나 수정하지 않고 구조
오류로 보고한다.

결정이 바뀌면 이전 기록을 지우지 않고 새 블록에 남긴다.

```markdown
- Revised: <이전> -> <현재> -> <이유>
```

기존 행동이 결정 변경, 부분 완료, 범위 확장·축소나 우선순위 변경으로 더는 현재의
정확한 행동이 아니면 완료로 표시하지 않는다. 체크박스를 제거하고 취소 이유를 붙인
뒤 새 행동을 기록한다.

```markdown
- Cancelled Resume: <기존 행동> — <취소 이유 또는 대체 이유>
- [ ] Resume: <새 행동>
```

`Cancelled Resume:`은 행동이나 기능 자체를 반드시 폐기했다는 뜻이 아니다. 기존
포인터 문장 전체를 활성 재개 지점에서 제거했다는 표시이며, 완료된 부분과 대체 의미는
새 블록 본문이 소유한다. 새 행동 없이 현재 로그에서 재개를 제거할 때도 같은 형식을
쓴다.

`Revised`는 결정·범위·판단의 의미 변경을 기록하고 Resume 전이는 재개 지점의 구조를
갱신한다. 결정이 바뀌어도 Resume이 계속 정확하면 유지하고, 행동도 바뀌면
`--replace-resume`, 불필요해지면 `--cancel-resume`을 사용한다.

## 외부 출처

외부 문서나 링크를 판단 근거로 사용했다면 결론의 근거가 된 URL, 확인한 사실과 그
사실이 판단에 미친 영향을 함께 기록한다. 판단에 사용하지 않은 검색 링크는 남기지
않고 원문을 길게 옮기지 않는다.
